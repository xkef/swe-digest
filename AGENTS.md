# Developing this repository

## Layout

```text
config.yaml             site, Worker, billing, run settings, watchlist, profile
.mise/                  mise config and tasks, formatter configs, and Vale
.github/                workflows, SECURITY.md, issue templates
agent/                  the Python program
  prompts/              rules.md, then daily.md or improve.md
  src/digest/           the package
  tests/
data/                   what runs write: digests, run records, follow-ups
site/                   the Zola site, generated by `mise run build`
signals/                the Cloudflare Worker for private feedback. See its README
```

A run may propose a new `watchlist` and `profile` in `config.yaml` through a
pull request. The publish gate refuses any other change, in `config.yaml` or
anywhere else. `build` writes `site/zola.toml` from `config.yaml`, and the
Worker's npm scripts pass its values to wrangler.

## Tasks

Every command is a mise task. `mise tasks` lists the ones to run by hand, and
`mise run <task>` runs one. Each task first runs the setup it needs. A fresh
clone doesn't need an install step.

| Task          | Does                                                            |
| ------------- | --------------------------------------------------------------- |
| `ci`          | run every check CI runs                                         |
| `build`       | check the data, generate the site content, and build into dist/ |
| `serve`       | serve the site at 127.0.0.1:3000                                |
| `test`        | run `pytest`                                                    |
| `fmt`         | format with `ruff`, `dprint`, and `rumdl`                       |
| `lock`        | upgrade every Python dependency in uv.lock                      |
| `daily`       | update today's digest, billed to the local `claude` login       |
| `improve`     | propose watchlist and profile changes                           |
| `worker`      | run the signals Worker at 127.0.0.1:8787                        |
| `worker-tail` | stream the deployed signals Worker's logs                       |

`mise tasks --hidden` also lists the tasks that others call: `setup:*` builds
the local environments, `ci:*` holds the checks that `ci` and the CI jobs run,
`install:*` installs from uv.lock in CI, `publish` is the
publish gate's entry point, and `check` checks the data alone.

`daily --replay` and `improve --replay` rerun a day from the model
reply saved under `.run/replies/`, without a new model call.

## Constraints

- **Only `agent.py` imports the agent SDK, and only `youtube.py` the transcript
  library.** The publish job installs uv.lock without the `agent` extra. A test
  fails if the publish path loads either.
- **The model never writes a file.** It answers in JSON, and Python validates
  and writes. A new capability becomes a new field in the answer.
- **Renovate updates every pin** in one weekly pull request, as configured in
  `.github/renovate.json5`.

## Writing

Comments, docstrings, and these documents follow
[Google's style guide for developer documentation](https://developers.google.com/style).
Write in present tense and active voice, with one idea per sentence. Avoid
idiom, and don't use an em dash, en dash, or semicolon. Comment why the code is
as it is, never what it used to be.
