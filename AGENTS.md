# Developing this repository

## Layout

```text
mise.toml               tools and environment. Tasks are in .config/mise/tasks/
.config/                the mise tasks, formatter configs, and Vale
.github/                workflows, SECURITY.md, issue templates
agent/                  the Python program
  config/               settings.yaml, watchlist.yaml, profile.md
  prompts/              rules.md, then daily.md or improve.md
  src/digest/           the package
  tests/
  requirements/         hash-pinned installs for CI: base.txt, agent.txt
data/                   what runs write: digests, run records, follow-ups
  runs/legacy/          run records of the previous pipeline
site/                   the Zola site, generated by `mise run site:build`
```

A run may propose changes to `agent/config/watchlist.yaml` and
`agent/config/profile.md` through a pull request. It may not change anything
else under `agent/`.

## Modules

| Module       | Does                                                   |
| ------------ | ------------------------------------------------------ |
| `daily.py`   | the daily run, top to bottom                           |
| `improve.py` | the weekly run                                         |
| `agent.py`   | the model call, its harness, and its billing check     |
| `sources.py` | collection from the watchlist                          |
| `http.py`    | bounded GET and the model's audited fetch              |
| `stories.py` | the digest format and its checks                       |
| `memory.py`  | follow-ups                                             |
| `runs.py`    | the run record                                         |
| `publish.py` | the publish gate                                       |
| `github.py`  | issues, signed commits, and pull requests through `gh` |
| `site.py`    | Zola content from the digest YAML                      |

## Tasks

Every command is a mise task, grouped by what it acts on. `mise tasks` lists
them, and `mise run <task>` runs one.

| Task            | Does                                                            |
| --------------- | --------------------------------------------------------------- |
| `agent:daily`   | update today's digest, billed to the local `claude` login       |
| `agent:improve` | propose watchlist and profile changes                           |
| `agent:publish` | check a run's files and publish them, in CI                     |
| `data:check`    | check every digest, run record, and follow-up                   |
| `site:build`    | check the data, generate the site content, and build into dist/ |
| `site:serve`    | serve the site at 127.0.0.1:3000                                |
| `deps:setup`    | create agent/.venv from uv.lock for development                 |
| `deps:lock`     | update uv.lock and both requirements files                      |
| `deps:base`     | install the publish dependencies, in CI                         |
| `deps:agent`    | install the agent dependencies, in CI                           |
| `dev:test`      | run `pytest`                                                    |
| `dev:lint`      | run `ruff` and `mypy`                                           |
| `dev:prose`     | lint the Markdown with Vale: Google style and ai-tells          |
| `dev:fmt`       | format with `ruff`, `dprint`, and `rumdl`                       |
| `dev:fmt-check` | check formatting without changing files                         |

## Constraints

- **Only `agent.py` imports the agent SDK.** The publish job installs
  `requirements/base.txt` alone. A test fails if the publish path loads the SDK.
- **The model never writes a file.** It answers in JSON, and Python validates
  and writes. A new capability becomes a new field in the answer.
- **Requirements files are generated.** `mise run deps:lock` rewrites them.

## Writing

Comments, docstrings, and these documents follow
[Google's style guide for developer documentation](https://developers.google.com/style):
present tense, active voice, one idea per sentence, no idiom, and no em dash, en
dash, or semicolon. Comment why the code is as it is, never what it used to be.
