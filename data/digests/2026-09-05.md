### Claude produced the first computer-checked proof of Fermat's Last Theorem in Lean

- **Category:** AI
- **Status:** confirmed
- **Sources:** [primary](https://www.anthropic.com/research/formalizing-fermats-last-theorem), [repository](https://github.com/anthropics/fermats-last-theorem), [Buzzard's account](https://xenaproject.wordpress.com/2026/09/04/flt-anthropic-has-beaten-me-to-it/), [discussion](https://news.ycombinator.com/item?id=49568506), [Buzzard thread](https://news.ycombinator.com/item?id=49570133)
- **Blurb:** Anthropic published a Lean proof of Fermat's Last Theorem written by Claude, and Kevin Buzzard compiled and checked it.
- **Summary:** Anthropic published on 2026-09-04 a Lean formalization of Fermat's Last Theorem written by Claude over 11 days, running to roughly 13 million lines with 30,300 theorems proved and 29,500 used. Lean checks the proof against its three standard axioms, and a comparator confirms the formal statement matches Mathlib's statement of the theorem. Kevin Buzzard writes on his own blog that he compiled the repository and ran the comparator himself.
- **Why it matters:** Buzzard's independent compilation makes this one of the few AI-produced results a reader can check rather than take on the vendor's word, and he states it adds no new mathematics.

### CISA adds an exploited Chromium V8 type confusion bug to the KEV catalog

- **Category:** Security
- **Status:** confirmed
- **Sources:** [NVD record](https://nvd.nist.gov/vuln/detail/CVE-2026-85046), [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?field_cve=CVE-2026-85046), [Chrome release note](https://chromereleases.googleblog.com/2026/09/stable-channel-update-for-desktop_01882797386.html), [discussion](https://news.ycombinator.com/item?id=49570669)

The NVD record scopes the defect to Google Chrome before 152.0.7977.82 and lists Chrome as the only affected product. The fixed version comes from that record because the Chrome Releases post body returned empty to automated fetch.

### GitHub opens Project HydraFusion as a research preview in Copilot CLI

- **Status:** confirmed

- **Blurb:** GitHub previews Project HydraFusion in Copilot CLI, a runtime orchestrator that routes each request across multiple models.

### The Rust React Compiler ships natively in Vite

- **Category:** Dev tools
- **Status:** confirmed
- **Sources:** [primary](https://blog.master.dev/react-now-rusted-all-the-way-out/), [discussion](https://news.ycombinator.com/item?id=49567873)
- **Blurb:** The Rust React Compiler now runs natively in Vite, cutting one 1,036-file compile from 14.3 seconds to 0.81 seconds.
- **Summary:** The author measures the compiler step on a 1,036-file project at 14.3 seconds before and 0.81 seconds after, and the whole build at 22.1 seconds before and 9.3 seconds after. The headline speedup of 17.6 times describes the compiler step alone. The oxc-based compiler also handles try/catch conditionals and computed object property keys that made the Babel-based v1.0 compiler bail out.
- **Why it matters:** The durable gain is broader compilation coverage rather than the headline multiple, since the build-level improvement is closer to 2.4 times.

- **Blurb:** A preprint measures LLM judges well short of the noise ceiling when scoring which chain-of-thought steps actually mattered.

## Agentic coding

### Spotify publishes a Claude Code plugin that blocks large file reads

- **Category:** Agentic coding
- **Status:** confirmed
- **Sources:** [primary](https://engineering.atspotify.com/2026/9/portal-by-spotify-cut-my-claude-code-token-usage-by-90), [discussion](https://news.ycombinator.com/item?id=49571465)
- **Blurb:** Spotify ships a Claude Code plugin whose hook blocks large file reads and routes them to a cheaper worker model instead.
- **Summary:** The enforcement sits in a PreToolUse hook that blocks any Read above a configurable line threshold and delegates the file to a cheaper worker model. The 90 percent figure is the mean saving on the bulk-read path across four scenarios, not a whole-workload reduction, and it is Spotify's own benchmark of Spotify's own product on one Java monorepo. The post states the limits: delegated summaries carry no reliable line numbers for editing, and the worker model missed a thread-safety bug the frontier model caught.
- **Why it matters:** A blocking hook enforces a context budget that advisory CLAUDE.md rules do not, at a stated cost in edit precision.

### An ISSTA 2026 study finds most rustc soundness bugs persisted since feature introduction

- **Category:** Paper
- **Status:** confirmed
- **Sources:** [preprint](https://arxiv.org/abs/2608.28713), [publisher record](https://doi.org/10.1145/3832220), [discussion](https://news.ycombinator.com/item?id=49571006)
- **Blurb:** An ISSTA 2026 study of 30 rustc soundness bugs finds most persisted from the day the underlying feature was introduced.
- **Summary:** The study examines 30 soundness bugs in rustc and reports that the bugs compromising memory safety cluster on implied bounds and trait objects. ### Reconstructing a Jane Street ASIC from GDS geometry and solving it with z3

- **Category:** Engineering post
- **Status:** confirmed
- **Sources:** [primary](https://jestoph.com/2026/09/04/jane-street-challenge.html), [discussion](https://news.ycombinator.com/item?id=49562657)
- **Blurb:** A month-long write-up reconstructs a Jane Street ASIC from GDS geometry into Verilog and solves the puzzle with z3.
- **Summary:** The author recovers a netlist from roughly 17,000 polygons by testing layer adjacency and polygon overlap, then lifts it to Verilog. The 120-cycle circuit is inverted by expressing the desired final state as z3 constraints rather than searching a 120-bit input space.
- **Why it matters:** Both halves of the method transfer outside the puzzle, to netlist recovery from layout and to constraint-solving instead of brute-forcing a wide input.
