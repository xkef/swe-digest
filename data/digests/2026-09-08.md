## Top stories

### Broadcom removed the public VMware VDDK downloads that migration tooling depends on

- **Category:** Infrastructure
- **Status:** developing
- **Sources:** [primary](https://www.virtualizationhowto.com/2026/09/leaving-vmware-just-got-harder-after-broadcom-pulled-vddk-downloads/), [discussion](https://news.ycombinator.com/item?id=49602699)
- **Blurb:** Broadcom pulled the public VMware VDDK downloads that Azure Migrate, Nutanix Move and virt-v2v need for agentless migration.
- **Summary:** The Broadcom download pages for the VMware Virtual Disk Development Kit now return errors, and Broadcom has published no announcement, deprecation notice, or replacement. Broadcom support told one customer the VDDK moved into VMware's Technology Alliance Program, and a Red Hat support article directs customers to contact Broadcom support to request access. Azure Migrate, Red Hat Migration Toolkit for Virtualization, Nutanix Move, virt-v2v and nbdkit all require the VDDK for agentless VMware migration.
- **Why it matters:** Teams mid-migration off VMware now need a support request to obtain the copy path their tooling is built on, with no public vendor statement to plan against.
- **Follow-up:** Track a Broadcom statement, a restored download path, or a documented replacement interface.

### CERN moves 2,200 accelerator control computers from CentOS to Debian over the x86-64-v2 baseline

- **Category:** Linux/Kernel
- **Status:** confirmed
- **Sources:** [primary](https://lwn.net/SubscriberLink/1092512/45bba78661c89e5a/), [discussion](https://news.ycombinator.com/item?id=49604026)
- **Blurb:** CERN moved 2,200 accelerator control machines from CentOS to Debian rather than fund a 5.4 million franc upgrade.
- **Summary:** CERN is moving 2,200 accelerator control computers from CentOS to Debian. A compiler baseline of x86-64-v2 would have left 47 percent of those control systems unable to boot, and another 17 percent would have failed under x86-64-v3, close to 65 percent in total. CERN put the estimated total cost of upgrading the affected machines at 5.4 million Swiss francs, which covers engineers, technicians, added rack space, and possible excavation rather than hardware alone.
- **Why it matters:** A distribution's microarchitecture baseline is a hardware retirement schedule for any fleet with long-lived embedded machines.

### Naming a test or verification technique to a coding agent does not beat giving it no instruction

- **Category:** Agentic coding
- **Status:** confirmed
- **Sources:** [primary](https://danluu.com/agentic-testing/), [discussion](https://news.ycombinator.com/item?id=49605246)
- **Blurb:** A 26-condition eval on codex with GPT-5.6 Sol found naming a technique or library did not beat the no-instruction default.
- **Summary:** The evaluation ran 26 prompt conditions at 80 runs each on a Zstd implementation task, using codex with GPT-5.6 Sol at medium and xhigh effort levels. No condition wildly outperformed, and the default condition, which gave the agent no testing instruction, scored well above the average across conditions. Agents given the name of a technique or a library applied it superficially rather than to the code most likely to hold the bug.
- **Why it matters:** Prompt boilerplate that names fuzzing or property testing did not outperform the default on this task and this model.

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://mcpherrin.ca/2026/09/07/rsa.html), [discussion](https://news.ycombinator.com/item?id=49604637)
- **Blurb:** A researcher factored both 512-bit E-Certify root keys from Netscape 4.51 in 32 and 29 hours on one desktop Ryzen.
- **Summary:** A researcher ran CADO-NFS on a single Ryzen 9 5950X desktop to factor two 512-bit RSA certificate authority root keys that shipped in the Netscape 4.51 trust store. The two E-Certify root private keys were recovered in 32 hours and 29 hours.
- **Why it matters:** It puts a measured single-machine cost on RSA key sizes that once anchored browser trust stores.

### TALA, the D2 orthogonal layout engine, is open-sourced under MPL-2.0

- **Category:** Dev tools
- **Status:** confirmed
- **Sources:** [primary](https://d2lang.com/blog/tala-is-open-source/), [discussion](https://news.ycombinator.com/item?id=49604150)
- **Blurb:** D2's orthogonal layout engine TALA is now MPL-2.0 and bundled in D2 v0.9.0, so --layout=tala needs no separate license.
- **Summary:** TALA, the orthogonal layout engine for the D2 diagram language, is released under MPL-2.0, the same license as D2. It ships bundled in D2 v0.9.0, so `--layout=tala` no longer requires a separate license. Node coordinates can be pinned while the engine still handles routing.
- **Why it matters:** Diagram-as-code pipelines can use the layout engine in CI without a per-seat license step.

### The bzip3 thread turns into a dispute over compression benchmark window sizes

- **Category:** Dev tools
- **Status:** discussion
- **Sources:** [repository](https://github.com/iczelia/bzip3), [discussion](https://news.ycombinator.com/item?id=49598291)
- **Blurb:** An HN commenter reports zstd with --long=29 compresses more than 2x smaller than bzip3 and at half its own default-window CPU time.
- **Summary:** A Hacker News thread on the bzip3 compressor moved from the project's headline comparison to the window sizes the comparison was run at.
- **Comments:** An HN commenter reports that matching zstd's window to bzip3's 512MB block with `--long=29` produces output more than twice smaller than bzip3. The same comment gives zstd -T8 -16 at 2054.50 seconds user time and the same command with `--long=29` at 1083.06 seconds, so the CPU-time halving is measured against zstd's own default window and not against bzip3, which the thread does not time.
- **Why it matters:** It reframes the project's published size advantage as a configuration artifact, which is the usual failure mode of compressor benchmarks.
