## Top stories

### C2PA signatures can be crafted to cover zero bytes of the file they sign

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://www.da.vidbuchanan.co.uk/blog/hacking-time.html), [discussion](https://news.ycombinator.com/item?id=49946707)
- **Blurb:** A malicious C2PA signer can declare the whole file an excluded range, so a valid signature and trusted timestamp cover nothing.
- **Summary:** C2PA lets a signer mark byte ranges as excluded from the hash, and David Buchanan's post dated 2026-10-02 shows that a malicious signer can declare the entire file excluded, so a valid claim signature and a valid RFC 3161 trusted timestamp both attest to an empty string. He timestamped a photo of a lottery ticket before the draw, edited the winning numbers in afterwards, and every C2PA verification tool he tested accepted the result. The flaw is in the C2PA specification's exclusion feature rather than in a single implementation, so no patched version exists and the feature cannot simply be removed, because formats such as PNG need it for CRC32 fixups, and the mitigation Buchanan proposes is a per-format allowlist of exclusion ranges that verifiers enforce.
- **Why it matters:** C2PA is the content-provenance standard camera vendors and AI tooling are adopting, and a signature covering zero bytes removes the one guarantee the standard exists to provide.
- **Follow-up:** Watch for a C2PA specification change that requires verifiers to enforce per-format exclusion-range allowlists.

### Critical Gitea Actions runner flaw gives workflow authors root on the runner host

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://github.com/advisories/GHSA-x4q3-gcj3-m6cf), [fix release](https://gitea.com/gitea/runner/releases/tag/v3.0.0), [pull request](https://gitea.com/gitea/runner/pulls/1058)
- **Blurb:** On a shared Docker-backed Gitea Actions runner, a workflow author can reach root on the host even with privileged mode off.
- **Summary:** GHSA-x4q3-gcj3-m6cf, CVE-2026-73802 at CVSS 9.9, records that a shared Docker-backed Gitea Actions runner appends a workflow's `container.options` to the Docker HostConfig, so the workflow author escalates to root on the host the runner sits on, and turning privileged mode off does not prevent it. Versions below the pseudo-version 1.0.9-0.20260731160927-34bfa1915022 are affected, which is the patched version the advisory records, and the same change reaches users as the Gitea runner v3.0.0 release carried in runner pull request 1058. The advisory was disclosed 2026-08-15 and entered the GitHub Advisory Database on 2026-10-02, so it is a seven-week-old disclosure newly indexed rather than a fresh one.
- **Why it matters:** A shared Docker-backed Gitea Actions runner can still be rooted by anyone able to push a workflow to it, so self-hosted CI operators have to upgrade the runner instead of relying on privileged mode being off.

### Go 1.27 extends its experimental SIMD API from amd64 to arm64 and wasm

- **Category:** Languages
- **Status:** confirmed
- **Sources:** [primary](https://go.dev/blog/archsimd), [discussion](https://www.reddit.com/r/golang/comments/1wwpfbh/archspecific_simd_in_go_the_go_programming/)
- **Blurb:** Go 1.27's experimental simd package extends from amd64 AVX-512 to arm64 NEON and the 128-bit wasm vector set.
- **Summary:** The Go blog post covers the `simd` and `archsimd` packages behind `GOEXPERIMENT=simd`, which now reach AVX through AVX-512 on amd64, NEON on arm64, and the 128-bit wasm vector set, with one method name shared across widths and architectures and masks as opaque types the compiler fuses into single instructions where the hardware allows. The post is explicit that CPU feature checks are required to avoid SIGILL and also act as optimization hints, and that loop bounds have to be written so the prove pass can drop bounds checks. The API stays experimental, and SVE, SVE2, riscv64, ppc64, s390x, and loong64 are listed as future work.
- **Why it matters:** Writing SIMD in Go has required hand-written assembly, and a portable experimental API changes what a Go hot loop can reach without dropping out of the language.
- **Follow-up:** Watch whether the simd and archsimd packages leave GOEXPERIMENT and which of SVE, riscv64, and the remaining architectures land first.

## AI

### Independent Kolibri walkthrough measures a larger German tokenizer advantage than the vendor claims

- **Category:** AI
- **Status:** discussion
- **Sources:** [primary](https://tej.as/blog/aleph-alpha-kolibri), [discussion](https://news.ycombinator.com/item?id=49943034)
- **Blurb:** An independent Kolibri walkthrough measures 15 percent fewer German tokens than the GPT-5 tokenizer, above Aleph Alpha's 11.2 percent.
- **Summary:** The post distils Aleph Alpha's 189-page technical report, the model card, and the launch post into six design choices: 50 layers of 384 experts plus one shared expert with 6 routed per token, giving 78.1B total and 3.46B active parameters, a 128,000-token UniBPE vocabulary, sliding-window attention on 40 of 50 layers with only those layers carrying rotary position embeddings, which is what lets context stretch past the 262,144 tokens it was trained on to a validated 1,048,576, German-language reasoning training, a per-request `reasoning_effort` selector, and Merlin-Arthur abstention training. The author ran his own tokenizer comparison over the German Basic Law and measured 15 percent fewer tokens than the GPT-5 tokenizer, a larger reduction than the 11.2 percent Aleph Alpha claims rather than a reproduction of it, and he also lists the weak rows: last of twelve on a closed-book test, 39.8 on multi-turn Berkeley Function Calling against 54.0 for Qwen3.5 35B-A3B, and 27.7 on Terminal-Bench 2.1. Benchmark comparisons otherwise come from Aleph Alpha's own evaluation, and the author discloses a friendship with a member of the team.
- **Why it matters:** The tokenizer measurement is the one number in the post a reader can reproduce independently, and it lands above the vendor's figure on a corpus the author chose himself.

### Quadratic SVG parsing in probe-image-size blocks the Node event loop on crafted input

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://github.com/advisories/GHSA-gjj5-9665-rwrc), [fix release](https://github.com/nodeca/probe-image-size/releases/tag/7.4.0)
- **Blurb:** A crafted SVG makes probe-image-size parse quadratically and stall a Node event loop at full CPU, fixed in 7.4.0.
- **Summary:** GHSA-gjj5-9665-rwrc, CVE-2026-104861 at CVSS 7.5, records quadratic complexity in the SVG handling of probe-image-size, so a small crafted response holds the Node event loop at full CPU. Versions through 7.3.0 are affected, and release 7.4.0 fixes both the synchronous path and the stream path. The advisory was disclosed 2026-08-15 and entered the GitHub Advisory Database on 2026-10-02.
- **Why it matters:** Any upload validator, image proxy, or link unfurler that calls probe on a remote URL can be stalled at full CPU by a small crafted response, and 7.4.0 fixes both the sync and the stream path.

### SiYuan agent tools reach internal addresses through a DNS rebinding SSRF bypass

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://github.com/advisories/GHSA-x8gv-g2g3-65fj)
- **Blurb:** SiYuan's agent tools can be pointed at internal addresses, because its SSRF guard and its dialer resolve the hostname twice.
- **Summary:** GHSA-x8gv-g2g3-65fj, CVSS 8.2, records that SiYuan's SSRF protection resolves a supplied hostname to check it against blocked ranges, and the HTTP dialer then resolves the same hostname again when it makes the request. An attacker who controls the DNS answer can return an internal address on the second lookup, so the agent tools fetch from the internal network past the guard. Versions through 3.8.0 are affected and 3.8.1 carries the fix, and the advisory was disclosed 2026-08-13 and entered the GitHub Advisory Database on 2026-10-02.
- **Why it matters:** The guard resolves the hostname once and the dialer resolves it again, a split any agent tool that fetches a model-supplied URL can reproduce.

### Nolan Lawson argues the case against "use the platform" before defending it

- **Category:** Engineering post
- **Status:** discussion
- **Sources:** [primary](https://nolanlawson.com/2026/10/03/why-dont-more-developers-use-the-platform/), [discussion](https://news.ycombinator.com/item?id=49950554)
- **Blurb:** Nolan Lawson argues the platform-skeptic case, then names browser lag and better npm docs as the reasons behind it.
- **Summary:** The post takes the platform-skeptic side seriously and names the causes: browsers spent years behind the library ecosystem, npm packages documented themselves better than the platform did, and building a modal yourself teaches more than reaching for the `dialog` element. Lawson generalises past the web with a ClickHouse example where he and a coworker each built compression and key-value indirection that the columnar store already did better. - **Why it matters:** It gives a concrete account of why teams rebuild what a platform already provides, which is the decision an AI-assisted codebase now makes at higher volume.
