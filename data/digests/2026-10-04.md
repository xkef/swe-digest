### Critical Gitea Actions runner flaw gives workflow authors root on the runner host

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://github.com/advisories/GHSA-x4q3-gcj3-m6cf), [fix release](https://gitea.com/gitea/runner/releases/tag/v3.0.0), [pull request](https://gitea.com/gitea/runner/pulls/1058)
- **Blurb:** On a shared Docker-backed Gitea Actions runner, a workflow author can reach root on the host even with privileged mode off.
- **Summary:** GHSA-x4q3-gcj3-m6cf, CVE-2026-73802 at CVSS 9.9, records that a shared Docker-backed Gitea Actions runner appends a workflow's `container.options` to the Docker HostConfig, so the workflow author escalates to root on the host the runner sits on, and turning privileged mode off does not prevent it. Versions below the pseudo-version 1.0.9-0.20260731160927-34bfa1915022 are affected, which is the patched version the advisory records, and the same change reaches users as the Gitea runner v3.0.0 release carried in runner pull request 1058. The advisory was disclosed 2026-08-15 and entered the GitHub Advisory Database on 2026-10-02, so it is a seven-week-old disclosure newly indexed rather than a fresh one.
- **Why it matters:** A shared Docker-backed Gitea Actions runner can still be rooted by anyone able to push a workflow to it, so self-hosted CI operators have to upgrade the runner instead of relying on privileged mode being off.

## Security

### Quadratic SVG parsing in probe-image-size blocks the Node event loop on crafted input

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://github.com/advisories/GHSA-gjj5-9665-rwrc), [fix release](https://github.com/nodeca/probe-image-size/releases/tag/7.4.0)
- **Blurb:** A crafted SVG makes probe-image-size parse quadratically and stall a Node event loop at full CPU, fixed in 7.4.0.
- **Summary:** GHSA-gjj5-9665-rwrc, CVE-2026-104861 at CVSS 7.5, records quadratic complexity in the SVG handling of probe-image-size, so a small crafted response holds the Node event loop at full CPU. Versions through 7.3.0 are affected, and release 7.4.0 fixes both the synchronous path and the stream path. The advisory was disclosed 2026-08-15 and entered the GitHub Advisory Database on 2026-10-02.
- **Why it matters:** Any upload validator, image proxy, or link unfurler that calls probe on a remote URL can be stalled at full CPU by a small crafted response, and 7.4.0 fixes both the sync and the stream path.

### SiYuan agent tools reach internal addresses through a DNS rebinding SSRF bypass

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://github.com/advisories/GHSA-x8gv-g2g3-65fj)
- **Blurb:** SiYuan's agent tools can be pointed at internal addresses, because its SSRF guard and its dialer resolve the hostname twice.
- **Summary:** GHSA-x8gv-g2g3-65fj, CVSS 8.2, records that SiYuan's SSRF protection resolves a supplied hostname to check it against blocked ranges, and the HTTP dialer then resolves the same hostname again when it makes the request. An attacker who controls the DNS answer can return an internal address on the second lookup, so the agent tools fetch from the internal network past the guard. Versions through 3.8.0 are affected and 3.8.1 carries the fix, and the advisory was disclosed 2026-08-13 and entered the GitHub Advisory Database on 2026-10-02.
- **Why it matters:** The guard resolves the hostname once and the dialer resolves it again, a split any agent tool that fetches a model-supplied URL can reproduce.
