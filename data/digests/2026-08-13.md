### Rapid7 publishes a proof-of-concept for critical SharePoint auth bypass CVE-2026-55040, and a threat intelligence firm reports it used against honeypots

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://services.nvd.nist.gov/rest/json/cves/2.0?cveId=CVE-2026-55040), [advisory](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-55040), [report](https://www.bleepingcomputer.com/news/microsoft/hackers-leverage-new-microsoft-sharepoint-exploit-in-attacks/), [discussion](https://www.reddit.com/r/cybersecurity/comments/1vmdc44/hackers_leverage_new_microsoft_sharepoint_exploit/)
- **Summary:** NVD carries CVE-2026-55040 from the `secure@microsoft.com` CNA at CVSS 3.1 9.1 Critical under CWE-1390, vector `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N`, so exploitation needs no credentials and no user interaction over the network, with high confidentiality and integrity impact and none to availability. The record was published 2026-07-14 and last modified 2026-08-13, it names the fixed builds as SharePoint Enterprise Server 2016 at 16.0.5561.1001, SharePoint Server 2019 at 16.0.10417.20175, and SharePoint Server Subscription Edition at 16.0.19725.20434, and its CISA SSVC entry scores exploitation as `poc`, automatable as `yes`, and technical impact as `total`. BleepingComputer reports that Rapid7 published proof-of-concept exploit code on 2026-08-11 in a write-up it credits to Stephen Fewer, and that threat intelligence firm Defused observed that code used against its SharePoint honeypots the next day, an observation that is Defused's own and that Microsoft has not matched with an exploited-in-the-wild flag.
- **Why it matters:** Public exploit code now exists for an unauthenticated network bypass on a server class that sits inside corporate perimeters holding documents, the patch has been available since the July 2026 Patch Tuesday, and the named build numbers turn the response into a version comparison rather than a triage exercise.
- **Follow-up:** Track whether Microsoft flags the CVE as exploited in the wild and whether CISA adds it to the Known Exploited Vulnerabilities catalog.

## Apple platforms

### SLAC, a CPU-to-GPU side-channel attack on the Apple Silicon system-level cache, is accepted to ACM CCS 2026

- **Category:** Paper
- **Status:** developing
- **Sources:** [primary](https://arxiv.org/abs/2608.09075), [HN submission](https://news.ycombinator.com/item?id=49281360)
- **Summary:** The paper names the attack SLAC and reverse-engineers the Apple M1 system-level cache set-indexing functions to build two channels. CPrime+CProbe primes and probes the shared cache from an unprivileged CPU process, and GPrime+CProbe leverages the GPU for faster priming, which the abstract credits with a 6.4x increase in covert-channel throughput. The authors report recovering LLM input keywords at up to 94.8 percent accuracy against TinyLlama and GPT-2 Medium, and the abstract does not attribute that figure to either channel. The paper is accepted to ACM CCS 2026, and it names no CVE, no vendor advisory, and no mitigation.
- **Why it matters:** Local inference on Apple Silicon currently assumes the CPU and GPU boundary holds, and CPrime+CProbe crosses it from an unprivileged CPU process through shared cache.
- **Follow-up:** Watch for an Apple advisory or a mitigation response.

## Infrastructure

### Deno Land open-sources celld, which runs Cloudflare Workers and Durable Objects on your own nodes with a bucket as the only coordinator

- **Category:** Infrastructure
- **Status:** confirmed
- **Sources:** [primary](https://celld.dev/), [repository](https://github.com/denoland/celld), [discussion](https://news.ycombinator.com/item?id=49281839), [discussion](https://news.ycombinator.com/item?id=49279223)
- **Summary:** Each celld node embeds V8 and executes Wrangler bundles, each object is its own SQLite database continuously replicated to an S3-compatible or Google Cloud Storage bucket as LTX segments, and object-storage compare-and-swap decides which node owns a cell, so the design carries no membership protocol, no failure detector, and no consensus service. The repository is `denoland/celld` under Apache-2.0 with 3,300 stars and a `ry@deno.com` contribution address, pull requests are disabled, and the project asks for `git format-patch` by email under a contributor agreement assigning rights to Deno Land Inc. The figures on the project page are the project's own and were not reproduced here, including roughly 90 ms region-local durable write latency, RPO of 0, about 20 seconds to fail over after node loss, 0.47 MB of RAM per resident cell, and about 2,500 resident cells per 8 GB node, and the page states its own measurement conditions, that speed and density come from one node running trivial cells on an Apple M-series laptop over loopback while fleet activation p50 is 35.9 ms on a 2 vCPU node.
- **Why it matters:** The Durable Objects programming model has been reachable only by deploying to one vendor, and running the same code against storage and machines the operator picks changes the tenancy and the failure domain rather than only the bill.

### Chrome's partial IDCT scaling explains why small JPEGs render differently than in Firefox

- **Category:** Engineering post
- **Status:** confirmed
- **Sources:** [primary](https://guillaumetech.github.io/posts/jpg-scaling-chrome/), [discussion](https://news.ycombinator.com/item?id=49272549)
- **Summary:** Chrome delegates JPEG decoding to Skia and libjpeg-turbo, which decode at the closest eighth-denominator fraction and skip high-frequency coefficients. The author traces small-image rendering differences against Firefox to that partial IDCT path. A correction added on 2026-08-12 attributes part of the difference to the downsampling algorithm rather than the partial IDCT alone.
- **Why it matters:** An icon shipped as a JPEG and rendered at 15px loses its edge softening in one browser and not another.

### A tour of yy, the unnamed double-to-string algorithm living inside yyjson

- **Category:** Engineering post
- **Status:** confirmed
- **Sources:** [primary](https://vitaut.net/posts/2026/yy-dtoa/), [discussion](https://www.reddit.com/r/programming/comments/1vm65dm/the_fastest_doubletostring_algorithm_youve_never/)
- **Summary:** The post documents the double-to-string algorithm embedded in yyjson, which sits in the Schubfach family but needs one multiplication by a precomputed power of ten where classic Schubfach needs two or three, because the half-ulp band falls out as an integer shift of the same table entry. It walks a boundary case where a threshold bias that reads as an off-by-one is correcting for table truncation.
- **Why it matters:** Float formatting sits in the hot path of every JSON serializer, and the algorithm is unnamed and undocumented outside this library.
