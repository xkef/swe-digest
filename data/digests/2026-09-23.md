## Top stories

### Meta Muse zero-day let any local process hijack the agent's account token

- **Category:** Security
- **Status:** confirmed
- **Sources:** [report](https://arstechnica.com/security/2026/09/muse-metas-extraordinarily-privileged-ai-assistant-has-a-serious-0-day/), [discussion](https://news.ycombinator.com/item?id=49802030)
- **Blurb:** A macOS zero-day in Meta's Muse assistant let any local process steal the account token of an agent holding email and payment authority.
- **Summary:** Patrick Wardle of the Objective-See Foundation found that any local app or code can change an undocumented Muse setting controlling the transcription endpoint, so pointing it at an attacker-run server hands over the account token. Muse holds WhatsApp, email, calendar, and purchase authority, and the reported delivery path is a ClickFix-style single command run by the user. Ars Technica reported that more than 12 hours after publication Meta said it had released a hotfix, and that Amazon began blocking Muse from its site and asked Meta to remove Amazon from the experience. Ars gives no affected or fixed Muse version numbers.
- **Why it matters:** A single ClickFix-style command could take over an agent holding WhatsApp, email, calendar, and purchase authority on macOS.
- **Follow-up:** Track whether Meta narrows the account token scope for Muse and whether it explains routing transcription through the cloud.

## Developer tools

### Android 17 requires certificate transparency, breaking custom CAs used for HTTPS debugging

- **Category:** Dev tools
- **Status:** confirmed
- **Sources:** [primary](https://httptoolkit.com/blog/android-17-certificate-transparency/), [discussion](https://www.reddit.com/r/programming/comments/1wo04r9/android_17_enables_certificate_transparency_and/)
- **Blurb:** Android 17 requires certificate transparency by default, rejecting the local CAs that HTTPS debugging tools rely on.
- **Summary:** Tim Perry of HTTP Toolkit documents that Android 17 requires certificate transparency by default for all system-trusted certificates, for apps targeting API level 37 running on an Android 17 device. Certificates issued by a locally generated CA carry no signed certificate timestamps, so they are rejected even though the CA sits in the system store, which breaks HTTPS interception for app debugging, security and privacy research, ad filtering, and enterprise traffic inspection with errors such as NET::ERR_CERTIFICATE_TRANSPARENCY_REQUIRED and NOT_ENOUGH_SCTS. The OS released in June 2026, Samsung Galaxy Z devices shipped with it in August, other OEMs began updating in early September, and API 37 becomes obligatory for Play Store publishing by August 2027.
- **Why it matters:** Every interception tool now has to reimplement the workaround Perry describes, deriving CT log operator identities from the CA certificate, embedding self-issued SCTs, and injecting the log operator config into the device.
- **Follow-up:** Track whether other interception tools ship the SCT workaround and whether Google offers a supported debugging path.

## Languages and runtimes

### Rust stabilises the Allocator trait proposed in RFC 1398

- **Category:** Languages
- **Status:** confirmed
- **Sources:** [primary](https://github.com/rust-lang/rust/pull/156882), [discussion](https://news.ycombinator.com/item?id=49814183)
- **Blurb:** Rust merged stabilisation of the Allocator trait and the allocator parameter on Box and Vec, proposed in RFC 1398.
- **Summary:** PR #156882 merged on 2026-09-23, stabilising a subset of allocator_api under tracking issue #32838 and RFC #1398, with the remainder renamed allocator_ext. The stabilised surface is the unsafe Allocator trait with allocate and deallocate required and allocate_zeroed, grow, grow_zeroed, and shrink provided, plus the allocator parameter on Box<T, A> and Vec<T, A>, the Global and System allocators, and impls for references, Box, Rc, and Arc, with Allocator dyn-compatible, by_ref removed, and implementors now required not to unwind from any trait method or from drop. Two limits carry forward, since Box::into_pin is not yet available with custom allocators because of a variance soundness issue, handled for now by an unstable unsafe StaticAllocator marker trait, and the noalias hack on Box moves to an unstable NativeAllocator wrapper.
- **Why it matters:** No-std, embedded, and Rust for Linux work has waited on a stable allocator parameter since RFC 1398.
- **Follow-up:** Track which stable release carries this, because the change is merged to main and not yet in a release.
