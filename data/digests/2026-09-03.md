### Meta ships Muse Spark 1.3 to Muse Code and the Meta Model API, holding max reasoning back for safety testing

### GitHub measures that shortening agent tool output raised total task cost in its own harness

- **Category:** Agentic coding
- **Status:** confirmed
- **Sources:** [primary](https://github.blog/ai-and-ml/github-copilot/how-we-make-ai-coding-more-cost-efficient-without-sacrificing-task-quality/), [discussion](https://news.ycombinator.com/item?id=49545164)
- **Blurb:** GitHub reports that truncating agent tool output with RTK raised total token use and task time in its own harness.
- **Summary:** GitHub evaluated RTK, a utility that truncates shell output before the agent reads it, and reports that when the omitted text mattered the model sometimes reopened the original output or reran the command to recover what it needed, so the task on average used more tokens and took longer. GitHub scopes the result to the integration and workloads it tested rather than to output compression in general. It states the four changes it did ship were picked offline on agentic coding benchmarks and then validated in controlled online A/B experiments.
- **Why it matters:** Shortening each tool response is a common way to cut agent spend, and GitHub publishes a measurement in which that move raised the cost of the whole task rather than lowering it.
- **Follow-up:** Track whether GitHub publishes the harness or the workload set behind the RTK result.

### Cursor moves cloud-agent tool execution onto customer machines while the agent loop and transcripts stay in its cloud

- **Category:** Agentic coding
- **Status:** confirmed
- **Sources:** [primary](https://cursor.com/blog/self-hosted-machines), [discussion](https://news.ycombinator.com/item?id=49546217)

### Claude Code stores MCP OAuth tokens in a plaintext file on Linux and Windows

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://secretspec.dev/blog/claude-code-stores-oauth-tokens-in-plaintext/), [discussion](https://news.ycombinator.com/item?id=49545023)
- **Blurb:** A report finds Claude Code 2.1.257 storing MCP OAuth access tokens in a plaintext file on Linux and Windows.
- **Summary:** The report checks Claude Code 2.1.257 and finds `~/.claude/.credentials.json` holding a top-level `mcpOAuth` object with access tokens, at file mode 0600. This is not a discrepancy with Anthropic's credential-management documentation, which the author quotes as stating that macOS uses the Keychain with that file as fallback, that Linux uses the file at mode 0600, and that Windows uses the profile directory's access controls. The gap the post identifies is between that documentation and the MCP documentation's phrase stored securely, and it notes that Codex documents auto, file and keyring backends for the same data. The author publishes SecretSpec and the post's proposed remedy is SecretSpec's own SDK and provider integrations, so the remedy is self-interested while the observation is checkable against Anthropic's own pages.
- **Why it matters:** MCP server credentials on Linux and Windows sit behind file permissions rather than an OS keyring, so any process running as the user reads them.
- **Follow-up:** Track whether Anthropic adds a keyring backend for MCP OAuth tokens or reconciles the two documentation pages.

### Wasmi 2.0 reports a 2.2x execution speedup and publishes the interpreter design behind it

- **Category:** Languages
- **Status:** confirmed
- **Sources:** [primary](https://wasmi-labs.github.io/blog/posts/wasmi-v2.0/), [discussion](https://news.ycombinator.com/item?id=49521031)
- **Blurb:** Wasmi 2.0 reports a 2.2x geometric-mean speedup over 1.0 and publishes the interpreter changes behind it.
- **Summary:** The release note reports 2.2x over Wasmi 1.0 in geometric mean across the wasmi-benchmarks suite on an Apple M2 Pro, run on three hardware setups including AMD EPYC 7763 and Intel Xeon Platinum 8370C, against Wasm3, WAMR fast-interpreter, Wasmtime Pulley and Makepad Stitch, from a benchmark project the author states is reproducible. The post details the changes: four instruction dispatch modes, three accumulator registers held in hardware registers, and a single contiguous instance allocation that removes the dependent-load chain behind global access. It also records the costs, that the accumulator design requires copy instructions the previous design did not, and a rejected experiment that regressed performance on calls.
- **Why it matters:** Wasmi is the plugin and smart-contract runtime under Typst, Zellij, Soroban and Ripple, and the release publishes its method, its comparison set and its regressions rather than a single number.
- **Follow-up:** Track whether the benchmark suite is run independently on non-Apple hardware.

## Engineering posts

### A developer emulating fused multiply-add finds the same subnormal rounding bug in Rust's standard library and in musl libc

- **Category:** Engineering post
- **Status:** confirmed
- **Sources:** [primary](https://shnatsel.github.io/implementing-fma-finding-bugs-in-std/), [discussion](https://news.ycombinator.com/item?id=49539006)
- **Blurb:** A developer emulating fused multiply-add found the same subnormal rounding bug in Rust's std and in musl libc.
- **Summary:** The post is dated 2026-08-20 and reports two of the defects it describes already fixed, with the Rust standard library patch awaiting review and the musl fix not merged. Sergey Davidoff reports that Rust's `f32::mul_add` software fallback and `std::simd` mishandle rounding for subnormal values, that musl's `fmaf` carries the same check ignoring subnormals, and that musl credits the code to FreeBSD with copyright years 2005 to 2011, so he states it may have been copied further without knowing where. The path runs only on hardware without FMA, which he ties to about 15 percent of machines in the Firefox hardware survey lacking AVX2, plus 32-bit ARM and embedded targets, and he states the error is one least significant bit, that he does not know whether it matters, and that deterministic simulations across different machines would diverge.
- **Why it matters:** The post publishes the input bit patterns a=0x97000800, b=0x1cfff001, c=0x00010002 and states that `fmaf` must return 0x00010001 rather than the buggy 0x00010002, so a reader can run the case against their own toolchain.
- **Follow-up:** Track whether the Rust patch lands and whether musl merges a fix, and whether the FreeBSD-derived code appears in other libcs.
