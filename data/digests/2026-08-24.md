## Top stories

### A paid YouTube ad delivered a fake TradingView installer that roots macOS and intercepts every HTTPS session

- **Category:** Security
- **Status:** confirmed
- **Sources:** [SafeDep analysis](https://safedep.io/youtube-ad-fake-tradingview-macos-stealer/)
- **Summary:** SafeDep published an analysis on 2026-08-21 of one macOS implant recovered from a single compromised workstation. The chain begins with a click on an in-video YouTube advertisement dated 2026-07-26, passes through two attacker-owned redirect domains, and ends with the user running a package named as a TradingView installer. The implant gains root and intercepts HTTPS sessions through a rogue root certificate authority placed in the System keychain. The post describes the password capture both ways, once as a native dialog inside the trusted `Installer.app` flow and once as a fake prompt shown during installation, and does not reconcile the two. SafeDep links the campaign to WEEVILPROXY and JSCEAL, and states that link as an inference from architectural and delivery overlap rather than as a confirmed attribution. SafeDep names no affected macOS versions anywhere in the analysis. It names four host artifacts: a LaunchAgent whose plist is `com.microsoft.service.systemhelperwatcher.v8mgfk.plist`, a payload directory at `~/Library/Application Support/.com.microsoft.service.systemhelperwatcher.v8mgfk/`, a plaintext password cache at `/Users/Shared/.passwd`, and a local proxy listener on `127.0.0.1:49313`.
- **Why it matters:** Delivery was a paid placement on a mainstream ad platform, so the four named artifacts give defenders something concrete to hunt for on hosts where an ad-linked installer was run.

### PostgreSQL 19 turns lock-wait logging on by default and adds per-process-type log levels, WAL full-page-image bytes, and multixact stats

- **Category:** Infrastructure
- **Status:** developing
- **Sources:** [PostgreSQL 19 release notes](https://www.postgresql.org/docs/19/release-19.html), [ClickHouse write-up](https://clickhouse.com/blog/postgres-19-monitoring-whats-new)
- **Summary:** The PostgreSQL 19 release notes carry a set of monitoring and observability changes. Section E.1.3.1.4 enables lock-wait logging by default, allows `log_min_messages` levels to be specified by process type in a `type:level` format, adds WAL full-page-write bytes to `VACUUM` and `ANALYZE` logging, raises the xid and multixact wraparound warning threshold from 40 million to 100 million, and stops `log_autovacuum_min_duration` on its own from reporting analyze runs. Section E.1.3.1.3 adds reporting of bytes written to WAL for full page images in `pg_stat_wal` and `pg_stat_get_backend_wal`, and adds multixact statistics. Each claim here was checked against the release notes rather than taken from the ClickHouse write-up. The notes are current as of 2026-07-18, and the page records 19 Beta 3 as shipped 2026-08-13 with no release date set.
- **Why it matters:** Log parsers, metric collectors, wait-event dictionaries, and any alert keyed to the 40 million wraparound warning all need changes before the upgrade, and `log_autovacuum_min_duration` alone stops reporting analyze runs.
- **Follow-up:** Track the PostgreSQL 19 release date, which the release notes still leave unset.

### LLVM 23 cuts stage2-O3 compile time by 6.75 percent, and precompiled headers cut MSVC and Clang builds of LLVM by about 45 percent

- **Category:** Languages
- **Status:** confirmed
- **Sources:** [compile-time measurements](https://aengelke.net/llvm23-ct.html)
- **Summary:** The post, dated 2026-08-21, measures LLVM 23 compile time and reports a 6.75 percent reduction. The post states that all its performance numbers refer to the `stage2-O3` configuration on the LLVM compile-time tracker unless noted otherwise. It separately reports that building LLVM and Clang with precompiled headers cuts build time by about 45 percent, and that the precompiled-header build is on by default for MSVC and Clang and disabled for GCC, where extra template instantiations negate the benefit.
- **Why it matters:** Every project built with an LLVM-based toolchain inherits the compile-time change, and the precompiled-header default changes what building LLVM itself costs in CI on MSVC and Clang.

## Security

### Zimbra's own patch post places the exploited command injection in the SNMP component, and the CISA remediation date is 2026-08-24

- **Category:** Security
- **Status:** confirmed
- **Sources:** [Zimbra patch release post](https://blog.zimbra.com/2026/07/patch-release-update-zimbra-10-1-20/), [CISA KEV feed](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json), [CISA KEV catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)
- **Summary:** The CISA catalog entry for CVE-2026-73570 cites Zimbra's own patch release post in its notes field. That post is dated 2026-07-20, describes the flaw as a command injection in the SNMP monitoring component reachable when SNMP notifications are enabled, and calls 10.1.20 the permanent fix for the vulnerability disclosed in Zimbra's 2026-06-26 advisory. Affected builds are those before 10.1.20. CISA still describes the flaw as reachable through crafted SMTP requests, and neither source reconciles that difference. The remediation due date for federal agencies is 2026-08-24. The catalog is at version 2026.08.21 with no addition after this entry.
- **Why it matters:** The exposed population is any Zimbra build before 10.1.20, and the vendor names SNMP notifications as the precondition while CISA names crafted SMTP requests, so operators who cannot patch today have no single reliable mitigation to fall back on.
- **Follow-up:** Track whether any source reconciles the SMTP and SNMP descriptions of the same CVE.

### Cloudflare degraded D1, Durable Objects, and R2 in Hong Kong and Singapore for four and a half hours

- **Category:** Outage
- **Status:** confirmed
- **Sources:** [Cloudflare incident page](https://www.cloudflarestatus.com/incidents/ksy4vxmbkfdk), [Cloudflare incidents feed](https://www.cloudflarestatus.com/api/v2/incidents.json)
- **Summary:** Cloudflare reports errors and elevated latency for D1, Durable Objects, and R2 in the Hong Kong and Singapore colos from 03:53 to 08:28 UTC on 2026-08-24, with a fix implemented at 06:42 UTC. Cloudflare rates the impact minor and has published no root cause. The same incidents feed carries two prior degradations in the same product family within four days: Hong Kong Durable Objects and R2 from 14:59 to 15:19 UTC on 2026-08-21, and Dubai R2 on 2026-08-22. Cloudflare rates all three minor and has published no root cause for any of them, so no common cause is established.
- **Why it matters:** Workers applications reading or writing D1 databases or Durable Objects pinned to the Hong Kong and Singapore colos saw errors across a four and a half hour window, and the storage products behind them have now degraded three times in four days without a published cause.
- **Follow-up:** Track whether Cloudflare publishes a root cause covering the 2026-08-21, 2026-08-22, and 2026-08-24 storage degradations.

## Developer tools

### Firefox 155 beta adds QUIC version 2 and two WebAssembly proposals, and moves the captive-portal check to a new domain

- **Category:** Dev tools
- **Status:** developing
- **Sources:** [Firefox 155 release notes](https://www.mozilla.org/en-US/firefox/155.0/releasenotes/)
- **Summary:** The Firefox 155 beta release notes add support for QUIC version 2 and for two WebAssembly proposals. The captive-portal detection check moves from `detectportal.firefox.com` to `firefox-portal-detection.com`. The notes also cap CSS nesting at 75 levels of nested blocks and functions, and narrow support for `::-webkit-scrollbar`.
- **Why it matters:** Network allowlists and captive-portal appliances that name `detectportal.firefox.com` need the new host added, and the 75-level nesting cap and the narrowed `::-webkit-scrollbar` support are behaviour removals rather than additions.

- **Category:** Linux/Kernel
- **Status:** confirmed
- **Sources:** [LWN report](https://lwn.net/Articles/1090098/), [Phoronix report](https://www.phoronix.com/news/SMB3-CIFS-Maintainer-Change)
- **Summary:** LWN published "Mourning Steve French" on 2026-08-23, reporting the death in Jonathan Corbet's own voice and quoting Jeremy Allison. Phoronix had reported it earlier, attributing it to a social media post by a Samba developer. French maintained the in-kernel SMB client and CIFS code.
