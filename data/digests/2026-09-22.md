## Top stories

### WordPress patches critical unauthenticated path traversal that can reach RCE, backported to 4.7

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://github.com/WordPress/wordpress-develop/security/advisories/GHSA-7hp8-65ch-5whp), [discussion](https://news.ycombinator.com/item?id=49803959)
- **Blurb:** WordPress 7.1.2 fixes CVE-2026-87902, an unauthenticated path traversal that can reach code execution, backported to 4.7.37.
- **Summary:** The advisory covers CVE-2026-87902, CVSS v4 base score 9.2, published 2026-09-22, where an unauthenticated attacker can make `get_page_template()` resolution include a chosen readable local `.php` file outside the active theme directories. Reaching code execution requires two preconditions: the active child or parent theme contains a top-level directory whose name starts with `page-`, which covers Twenty Twelve, Twenty Fourteen, Neve, Hestia, and Sydney, and a chosen readable local `.php` target exists, for which the advisory names the PEAR `pearcmd.php` path with `register_argc_argv` set to On. The advisory states the official php Docker image is affected and the default cPanel configuration is affected on PHP before 8.5, and the fix ships in 7.1.2 with backports across 25 branches to 4.7.37.
- **Why it matters:** Attack vector is network with no privileges and no user interaction, and the backport reach to 4.7.37 means the upgrade applies to nearly every install still receiving WordPress security releases.

### Git 3.0 set for April 2027 with SHA-256, reftable, and Rust as defaults

- **Category:** Dev tools
- **Status:** confirmed
- **Sources:** [primary](https://lwn.net/SubscriberLink/1094575/2385e98583715c2b/), [discussion](https://news.ycombinator.com/item?id=49794736)
- **Blurb:** Git 3.0 ships April 2027 with SHA-256, reftable, and a mandatory Rust compiler as the defaults for all later releases.
- **Summary:** LWN reported on 2026-09-18, with an update from Kernel Recipes where Patrick Steinhardt described the agreed plan, that the December 2026 release is named 2.98 as a signal, 2.99 follows in April 2027 as a long-term-support release, and Git 3.0 ships at the same time as the base for all subsequent releases. Git 3.0 carries three compatibility breaks: SHA-256 becomes the default object hash instead of SHA-1, reftable becomes the default ref storage, which matters at Android-scale repositories holding over 800,000 refs, and Rust becomes mandatory to build Git. - **Why it matters:** Platforms without a working Rust compiler cannot upgrade past 2.99, and GitHub has announced no SHA-256 support, so the default hash change currently lands without a confirmed path for the largest hosting platform.
- **Follow-up:** Whether GitHub announces SHA-256 support before April 2027.

## Security

### Rust security team: Miri writes all environment variables into target/, exposing secrets through GitHub Actions caches

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://blog.rust-lang.org/2026/09/21/github-actions-leaking-secrets-when-miri-output-is-cached/)
- **Blurb:** Miri writes every environment variable into target/, so a cached target/ hands pull request authors the secrets.
- **Summary:** The Rust Security Response Team published on 2026-09-21 that `cargo miri` needs build-relevant environment variables preserved between runs and does so by storing all of them to `target/`, reported by Predrag Gruevski of OpenAI. Where `target/` is cached and the cache is readable by pull requests, which is the common `actions/cache` and `swatinem/rust-cache` setup, anyone who can open a PR can extract those secrets and then push a second commit to hide the run, and the ecosystem scan found 1 affected repository and 7 to be cautious about. The post names the fixed build, the 2026-09-22 nightly that restricts Miri to `CARGO_*` excluding `CARGO_*_TOKEN` plus `OUT_DIR`, rather than an affected version range, so every earlier `cargo miri` run under a publicly readable cache counts as exposed, and the stated mitigations are to disable the cache for that job, scope secrets away from Miri steps, or disable Miri, then clear the cache and rotate exposed secrets.
- **Why it matters:** The stated rule generalizes past Rust, because most tools assume the whole environment is writable to disk, so any job that can write to a publicly readable cache should not hold secrets.
- **Follow-up:** Whether other build tools are found writing the full environment into a cached directory.

### Expat 2.8.5 fixes CVE-2026-93990, malformed UTF-16 smuggling in surrogate pair validation

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://blog.hartwork.org/posts/expat-2-8-5-released/)
- **Blurb:** Expat 2.8.5 fixes CVE-2026-93990, where missing low-surrogate validation let malformed UTF-16 reach callers.
- **Summary:** Maintainer Sebastian Pipping released Expat 2.8.5 on 2026-09-22, fixing CVE-2026-93990, where versions before 2.8.5 did not validate that the second half of a surrogate pair falls in the low-surrogate range 0xDC00 to 0xDFFF. An attacker could therefore smuggle malformed UTF-16 into the calling application, where the damage depends on how that application handles it. Kartik Kenchi reported and fixed the flaw, and no exploitation is reported.
- **Why it matters:** libexpat is one of the two most widely used C XML parsers and is bundled or pinned in a very large number of downstream projects, so the maintainer's request reaches packagers and anyone carrying a bundled or pinned copy, not only direct dependents.

## Engineering posts

### Linear halves CI runner time per test while its suite nearly quadruples under agent-written code

- **Category:** Engineering post
- **Status:** confirmed
- **Sources:** [primary](https://linear.app/now/ci-bottleneck-reworked), [discussion](https://news.ycombinator.com/item?id=49792067)
- **Blurb:** Linear cut PR wait time from over 6 minutes to just over 5 while its test suite nearly quadrupled since January.
- **Summary:** Mufeez Amjad published the work on 2026-09-21 with numbers for each change: PR wait time fell from over 6 minutes to just over 5 and runner time per test roughly halved, while test suites almost quadrupled since January at roughly 2,000 tests added per week. Moving off GitHub Actions to third-party runners made jobs 34 percent faster on average and tsc 52 percent faster, tsgo cut the weekly median tsc check by 73 percent, rewriting type-aware lint rules to pure AST analysis cut full-repository lint time 55 percent and enabled the later Oxlint move, capping fetch depth took the slowest change-detection gate from 94 to 20 seconds, and consolidating seven small checks into two saved roughly 87,000 runner-minutes per month, 11.8 percent of total CI usage. The largest single win was an opt-in Vitest project with `isolate: false`, worth about 17 percent of monthly spend with the slowest shard falling from a range of 300 to 379 seconds down to about 195, and also the highest correctness risk, so they updated their agent skills to make generated tests respect the opt-in constraints.
- **Why it matters:** Sharding only pays once per-shard setup cost is low, and where agents write most of the tests the constraint has to live in the agent instructions rather than in review.

### Survey finds 78 percent of developers stop reading an article they believe is AI-assisted or AI-written

- **Category:** Engineering post
- **Status:** confirmed
- **Sources:** [primary](https://blog.colinbreck.com/i-dont-want-to-read-what-you-didnt-write/), [discussion](https://news.ycombinator.com/item?id=49794330)
- **Blurb:** A survey Colin Breck cites finds 78 percent of readers stop reading once they believe an article is AI-written.
- **Summary:** Colin Breck, writing 2026-09-20, cites Cynthia Dunlop's survey on AI-scented blog posts: 78 percent of readers stop reading when they believe an article is AI-assisted or AI-authored, 71 percent avoid the author in future, and 98 percent prefer the author's own writing with its flaws over an AI rewrite. His stated mechanism for why AI-generated documents read badly to everyone but their prompter is that the prompter holds the context that produced the output and can skim it, while the recipient has none and must read exhaustively. He reports the inverse split from writing an academic paper, where AI was valuable for verifying claims against source code, configuration, and production logs, for citations, for TikZ diagrams, and for catching a notation error four expert reviewers missed, while asking it to write a paragraph from that same context was never useful.
- **Why it matters:** The figures put a measured readership cost on publishing AI-written engineering prose, and Oxide now mandates that all public writing be reported human-authored by Pangram.
