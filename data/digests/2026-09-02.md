## Top stories

### A git config flaw runs attacker code in coding agents before the workspace-trust prompt

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://www.manifold.security/blog/ai-coding-agents-git-hijack), [discussion](https://news.ycombinator.com/item?id=49525561)
- **Blurb:** Manifold Security reports coding agents run a repository's `core.fsmonitor` program before the workspace-trust prompt.
- **Summary:** The report describes agent startup routines that run context-gathering `git` commands inside an opened repository without stripping the repository's own configuration, so a repository-local `core.fsmonitor` value naming a program is honoured, and the index refresh then runs that program with the developer's privileges and outside the agent sandbox, before any workspace-trust prompt appears. The researcher states four of eight findings were unpatched at publication, naming Claude Code ultrareview 2.1.252, Qwen Code 0.22.3, Grok Build 1.0.13 and Hermes 0.21.0, states that the Claude Code finding uses a different git setting of the same kind rather than `core.fsmonitor` and leaves that key unnamed while it is unpatched, and records OpenAI Codex and Cursor as affected and since patched in a 2026-09-01 update. The report records CVE-2026-72718 for Goose, scored 7.0 by the maintainers and assigned after the report, and CVE-2026-71963 for Hermes, assigned by VulnCheck as an independent CVE Numbering Authority rather than by the vendor, and states that clone, fetch and pull do not carry the vector, which requires a directory moved as files with `.git` already inside.
- **Why it matters:** Four of the eight findings were still unpatched at publication, and the command runs outside the agent sandbox with the developer's privileges before any approval prompt, so the agent permission model never sees it.
- **Follow-up:** Track whether the four agents unpatched at publication ship fixes and whether further CVEs are assigned.

### FBI investigates an apparent breach at idscan.net after a service lists 153 million license scans

- **Category:** Security
- **Status:** developing
- **Sources:** [primary](https://krebsonsecurity.com/2026/09/fbi-probes-service-selling-153m-drivers-licenses/), [discussion](https://news.ycombinator.com/item?id=49529621)
- **Blurb:** Krebs reports the FBI's New Orleans field office opened an investigation into an apparent breach at idscan.net.
- **Summary:** Krebs on Security reports that a dark web service advertises scans of more than 153 million driver's licenses, and that the FBI's New Orleans field office opened an official investigation into an apparent breach involving idscan.net, a New Orleans identity verification vendor. The attribution of the images to idscan.net is inferential in the reporting, resting on timestamp correlation between listed scans and a Hertz rental and a Planet13 dispensary rather than on a vendor confirmation. idscan.net told Krebs it has not reached conclusions regarding the nature or scope of the incident, and its own trust page names Hertz, Target, FedEx and Caesars.
- **Why it matters:** If the images did come from idscan.net, the exposure reaches every business that outsourced ID scanning to it, and its own trust page names Hertz, Target, FedEx and Caesars.
- **Follow-up:** Track whether idscan.net confirms a breach and whether any listed customer notifies affected users.

### Apple sets macOS 27 as the last release with general Rosetta support

- **Category:** Apple
- **Status:** confirmed
- **Sources:** [primary](https://developer.apple.com/news/?id=w5ngl9k2), [discussion](https://news.ycombinator.com/item?id=49526782)
- **Blurb:** Apple states macOS 27 is the last release with general Rosetta support, with an exception for older gaming titles.
- **Summary:** Apple's developer news post states that macOS 27, which ships this fall, is the final release supporting Rosetta, the translation layer that runs Intel binaries on Apple silicon, and that this concludes a transition announced at WWDC last year. The post carves out an exception, stating that Rosetta functionality for older, unmaintained gaming titles that rely on Intel-based frameworks continues to be supported. Apple states that macOS 26.4 begins showing users system notifications about applications that still ship Intel-only binaries.
- **Why it matters:** Every macOS app outside that gaming exception which still ships an Intel-only binary now has a dated deadline, and users see system notifications from macOS 26.4 first.
- **Follow-up:** Track the macOS 27 release date and whether Apple states which titles fall inside the gaming exception.

## Agentic coding

### GitHub Copilot code review can now approve pull requests in public preview

- **Category:** Agentic coding
- **Status:** confirmed
- **Sources:** [primary](https://github.blog/changelog/2026-09-01-copilot-code-review-can-now-approve-pull-requests/), [discussion](https://news.ycombinator.com/item?id=49529323)
- **Blurb:** GitHub put Copilot pull request approval into public preview, off by default and configurable at three admin levels.
- **Summary:** The GitHub changelog entry, dated 2026-09-01, states that Copilot code review can now approve a pull request, that the ability is off by default, and that it is configurable at the enterprise, organization and repository level. Repository admins can turn approvals on or off and choose which file paths Copilot is allowed to approve. GitHub states that an approval assessment alone does not count toward merge requirements, and that the feature is in public preview on the Copilot Pro, Pro+, Max, Business and Enterprise plans.
- **Why it matters:** An automated reviewer can now register an approval on a pull request, so what that approval is worth is decided by an admin setting at the enterprise, organization or repository level rather than by branch protection alone.
- **Follow-up:** Track whether the feature leaves public preview and whether GitHub changes the off-by-default posture.

### Cloudflare prototypes compressing its cache with Zstandard inside Pingora

- **Category:** Engineering post
- **Status:** confirmed
- **Sources:** [primary](https://blog.cloudflare.com/cache-transcoding/), [discussion](https://news.ycombinator.com/item?id=49521909)
- **Blurb:** Cloudflare published an intern prototype that recompresses cache objects to Zstandard inside its Pingora proxy.
- **Summary:** Cloudflare published a post describing an intern prototype that transcodes cached objects to Zstandard inside its Pingora proxy, and it publishes per-byte encode and decode costs alongside the compression ratio. The post reports 2.834x on a deliberately compressible two-asset corpus and states that a broader corpus is needed before treating that figure as fleet-wide. It also reports that restricting compression to hot assets performed worse than compressing all eligible text, and nothing described in the post is deployed.
- **Why it matters:** The post publishes the measured trade rather than a product claim, including per-byte encode and decode costs and the finding that restricting compression to hot assets performed worse than compressing all eligible text.
- **Follow-up:** Track whether Cloudflare measures the prototype against a representative corpus or moves any part of it into production.
