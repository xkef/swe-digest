## Top stories

### Torvalds publishes a page-cache patch series written with Claude Code and says so in the patch message

- **Category:** Agentic coding
- **Status:** confirmed
- **Sources:** [primary](https://www.phoronix.com/news/Linus-Torvalds-Claude-Code), [discussion](https://news.ycombinator.com/item?id=50050367)
- **Blurb:** Torvalds posted an unmerged page-cache patch series and disclosed in the patch message that he wrote it with Claude Code.
- **Summary:** Phoronix reports a Torvalds branch named `noref-filemap-read-with-llm` that reads from the page cache without taking folio references, which targets the reference-count contention that appears when many threads perform small reads of one file. The patch message states the work was done with Claude Code, and the branch is unmerged, with Phoronix speculating about the Linux 7.4 merge window rather than reporting a target Torvalds stated. This digest sources the branch name and the attribution line to Phoronix because `lore.kernel.org` refuses automated fetch from this environment.
- **Why it matters:** The kernel's maintainer documenting LLM-assisted authorship inside a memory-management patch series sets a concrete disclosure precedent for every project deciding how to handle agent-written code.
- **Follow-up:** Whether the series lands in the 7.4 merge window and whether kernel submission policy picks up an explicit LLM-disclosure convention.

### HashiCorp archives Boundary Community Edition with no further security patches planned

- **Category:** Infrastructure
- **Status:** confirmed
- **Sources:** [primary](https://github.com/hashicorp/boundary), [discussion](https://news.ycombinator.com/item?id=50049498)
- **Blurb:** HashiCorp archived the Boundary Community Edition repository and plans no further bug fixes or security patches.
- **Summary:** The `hashicorp/boundary` repository is archived and read-only. The README gives an archive date of 2026-10-08 and the repository banner dates the archive to 2026-10-09. The README states that no new Boundary CE releases, maintenance updates, bug fixes, or security patches are currently planned, which is a statement about what is planned rather than a commitment never to patch.
- **Why it matters:** Teams running Boundary CE for identity-based access to production infrastructure now run software with no releases, bug fixes, or security patches currently planned, so the choice is a migration or an exposure that grows with every unfixed flaw.
- **Follow-up:** Whether HashiCorp publishes a migration path for CE users and whether a community fork takes over patching.

### Sakana AI reports recursive self-improvement from multi-agent self-supervision, with uneven transfer

- **Category:** ML research
- **Status:** confirmed
- **Sources:** [primary](https://pub.sakana.ai/mass/), [discussion](https://news.ycombinator.com/item?id=50048522)
- **Blurb:** Sakana AI reports 1.2x to 1.6x gains per output token from multi-agent self-supervision, but below 1x on SWE-bench Verified.
- **Summary:** MASS applies multi-agent self-supervision to Qwen3.6-27B in the qwen-code agent environment and reports 1.2x to 1.6x score per output token after two rounds on MLR-Bench, DSBench, ScienceAgentBench, and AstaBench. The same configuration reports 0.96x on Terminal-Bench 2.0 and 0.94x on SWE-bench Verified. The post publishes the regressions alongside the gains.
- **Why it matters:** A team reading this as a route to cheaper coding agents gets nothing from it, because the two software engineering benchmarks are the ones where the method falls below its own baseline.

## Hacker News

### HN debates whether human review, not model capability, is now the binding constraint

- **Category:** AI
- **Status:** discussion
- **Sources:** [primary](https://twitter.com/karpathy/status/2109361546505966046), [discussion](https://news.ycombinator.com/item?id=50047422)
- **Blurb:** A 589-comment HN thread argues human code review, not model capability, is now the binding constraint on shipping.
- **Summary:** The thread responds to a post on Andrej Karpathy's own account arguing that the gap in shared understanding of LLM capability is widening. It runs 589 comments and centers on review capacity rather than on model benchmarks.
- **Comments:** Commenters report that code review at their own employers has become a formality, and argue from that experience that review throughput rather than model capability now sets the limit.
- **Why it matters:** If review is the binding constraint, the next throughput gain for a team comes from changing how changes get reviewed rather than from upgrading a model.

### Passkey criticism draws technical dissent over whether password managers restore user control

- **Category:** Security
- **Status:** discussion
- **Sources:** [discussion](https://news.ycombinator.com/item?id=50048312)
- **Blurb:** HN splits on passkeys, with commenters arguing KeePassXC and Bitwarden keep user control over the credentials.
- **Summary:** The thread splits over whether passkeys remove user control or whether holding them in a third-party password manager restores it.
- **Comments:** Commenters argue that passkeys stored in KeePassXC or Bitwarden keep the credential under user control, while conceding that site support for third-party managers is uneven.
- **Why it matters:** Choosing passkeys as a second factor now requires checking per-site support for third-party managers first, because that support is what decides whether the credential stays portable.
