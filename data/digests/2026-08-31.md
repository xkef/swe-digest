## Top stories

### JFrog Artifactory authentication bypass gives unauthenticated network attackers administrative access under default configuration

- **Category:** Security
- **Status:** confirmed
- **Sources:** [advisory](https://docs.jfrog.com/releases/docs/jfrog-security-advisories), [GitHub advisory](https://github.com/advisories/GHSA-c5pf-6p5j-gj87), [discussion](https://news.ycombinator.com/item?id=49502508)
- **Blurb:** JFrog rates an Artifactory authentication bypass 9.8, letting an unauthenticated network attacker gain admin under default configuration.
- **Summary:** JFrog's advisory, published 2026-08-28 and tracked as CVE-2026-82329, rates the flaw critical at CVSS 3.1 score 9.8 under CWE-287 and states that an unauthenticated attacker with network access may obtain administrative privileges under the default configuration. The affected and patched pairs per release branch are 7.111.4 through 7.111.21 patched in 7.111.21, 7.117.0 through 7.117.27 patched in 7.117.28, 7.125.0 through 7.125.19 patched in 7.125.20, 7.133.0 through 7.133.28 patched in 7.133.29, 7.146.0 through 7.146.36 patched in 7.146.38, and 7.161.0 through 7.161.19 patched in 7.161.20. The vendor page lists 7.111.21 as both the end of that branch's affected range and its fix, so an operator running 7.111.21 cannot resolve exposure from the advisory alone. JFrog states cloud environments are already remediated and need no action, the GitHub advisory is type unreviewed and lists no affected package ranges at all, no exploitation is reported, and EPSS is 0.377 percent.
- **Why it matters:** Artifactory holds build artifacts and repository credentials for many organizations, so every self-hosted release branch needs the patched build rather than a configuration change.
- **Follow-up:** The version table comes from the vendor page because the GitHub advisory carries no ranges, so a later reviewed advisory and any exploitation report need picking up.

### Asahi Linux posts initial USB4 and Thunderbolt support for Apple M1, M2 and M3 to the kernel lists

- **Category:** Linux/Kernel
- **Status:** confirmed
- **Sources:** [patch series](https://lore.kernel.org/asahi/20260830-b4-apple-soc-tbt-v1-0-44bc9348683c@kernel.org/), [author post](https://social.treehouse.systems/@sven/117186314116319619), [discussion](https://news.ycombinator.com/item?id=49502515)
- **Blurb:** Sven Peter posted 19 patches adding initial USB4 and Thunderbolt support for Apple M1, M2 and M3 to the kernel lists.
- **Summary:** The series, sent 2026-08-30, adds 3872 lines across 34 files, including a new drivers/thunderbolt/apple.c at 1028 lines, and states its own limits: only XDomain connections and USB3-over-USB4 tunnels work, PCIe and DisplayPort tunneling still need reverse engineering, and suspend is blocked while a connection is active because the machine would otherwise resume into an SError. Each USB4-capable Type-C port carries an Apple Converged I/O block with a Cortex-M3 co-processor, and the NHI and DART IOMMU sit as device-tree children reachable only through a 16 MiB MMIO window while that co-processor runs. The series depends on five other posted series, Peter suggests merging through the thunderbolt tree, and M1 and M2 device-tree nodes are included with M3 nodes to follow.
- **Why it matters:** This is the first Thunderbolt enablement for Apple Silicon under Linux, and the stated gaps set what a docking station can and cannot do on these machines.
- **Follow-up:** Track whether the series merges through the thunderbolt tree and when PCIe and DisplayPort tunneling land.

### Haiku R1/beta6 ships after two years with a new userland allocator and halved HaikuWebKit build time

- **Category:** Dev tools
- **Status:** confirmed
- **Sources:** [release notes](https://www.haiku-os.org/get-haiku/r1beta6/release-notes/), [announcement](https://www.haiku-os.org/news/2026-08-26_haiku_r1_beta6), [discussion](https://news.ycombinator.com/item?id=49499867)
- **Blurb:** Haiku R1/beta6 ships after two years, halving HaikuWebKit build time to 2h33m and replacing the default userland allocator.
- **Summary:** Haiku released beta6 on 2026-08-26 with over 530 bugs and enhancement tickets resolved. A full HaikuWebKit rebuild went from 4h53m on beta5 to 2h33m, and git status on a repository of over 160,000 files went from about 33s to about 20s with a cold disk cache and from about 15s to about 2.5s with a hot one, which the notes attribute mainly to a directory-entry cache that no longer needs a write lock to add entries and to read-write locking in the inode block cache. The default userland allocator is replaced with one based largely on OpenBSD's plus a global caching layer, retiring a long-standing hoard derivative, Firefox now ships with official Mozilla branding on x86_64, QEMU gains NVMM hardware virtualization, a Go 1.26.1 port landed without being upstreamed, and app_server can restart with applications reconnecting instead of requiring a reboot. The release is x86 32-bit and 64-bit only and the project states it is beta quality with no assurance against data loss.
- **Why it matters:** The release turns two years of kernel and memory-management work into measured build and filesystem gains, which is the part of a hobby OS release that transfers as engineering evidence.

### Independent testing maps what ChatGPT Work does that ChatGPT Chat cannot

- **Category:** AI
- **Status:** developing
- **Sources:** [primary](https://simonwillison.net/2026/Aug/30/understanding-chatgpt-work/), [discussion](https://news.ycombinator.com/item?id=49504625)
- **Blurb:** Simon Willison's testing puts ChatGPT Work's cloud version at 223 tools with open container egress and no published injection defense.
- **Summary:** Willison's account, dated 2026-08-30, is that two different products share the name: a cloud version reachable at chatgpt.com and in the mobile apps, and a local one inside the desktop app formerly called Codex, both limited to paid tiers at 20 US dollars per month and above. The cloud-only capabilities he identifies through testing are a code execution environment with outbound internet access that appears open by default rather than allowlisted, a headless Chrome instance that runs JavaScript against the DOM and hands off to the user for passwords and two-factor codes, a /workspace filesystem persisted and shared across concurrent sessions, deployment of ChatGPT Sites onto Cloudflare Workers with D1 and R2, sub-agents, and model selection across Sol, Luna and Terra. He had the agent document its own surface and got 223 registered tools, 6 of which are his own MCP servers, and 44 skills, and he contrasts the open container egress with Claude's much shorter domain allowlist. Status is developing because OpenAI announced the product on 2026-07-09 and has iterated since, the behavior is undocumented, and Willison states several conclusions as inference.
- **Why it matters:** Willison states the product combines private data, exposure to untrusted content and an outbound channel, the three conditions he calls the lethal trifecta, and that OpenAI has not published how Work sessions are defended against prompt injection.

## Agentic coding

### Open Codex issue reports the Memories feature sending local-provider conversations to OpenAI

- **Category:** Agentic coding
- **Status:** developing
- **Sources:** [issue](https://github.com/openai/codex/issues/41711), [discussion](https://news.ycombinator.com/item?id=49501565)
- **Blurb:** A Codex issue reports the Memories feature sending prior local-provider conversations to OpenAI when memory generation runs.
- **Summary:** The issue, opened 2026-08-30, states that Codex's memory writer selects an eligible prior rollout without binding the candidate to the provider that created it, citing a selector call made with model_providers set to None, and then serializes that transcript and sends it through whichever provider is active in the session that triggered memory generation. The reporter says the crossover was reproduced against the Windows desktop binary 0.150.0-alpha.12.2 with analytics disabled and every OpenTelemetry exporter set to none, and gives a step-by-step reproduction. Maintainers have labeled the issue bug, app, custom-model and memory. Two claims in the report are separate from that code-path finding and are not established: the reporter's belief that OpenAI used such content for account moderation, and the characterization of the transfer as deliberate. OpenAI has not responded on the issue.
- **Why it matters:** Anyone running Codex against a local or third-party model with Memories enabled has no way to scope memory generation to the originating provider, and the only control the report identifies is turning the feature off with `[features] memories = false`.

## Engineering posts

### Domain autocomplete over 240 million names pairs an in-memory trie with a memory-mapped block index

- **Category:** Engineering post
- **Status:** confirmed
- **Sources:** [primary](https://ruurtjan.com/articles/p99-0ms-autocomplete-for-240-million-domain-names), [discussion](https://news.ycombinator.com/item?id=49505219)
- **Blurb:** Ruurtjan Pul serves autocomplete over 240 million domain names with an in-memory trie plus a memory-mapped block index.
- **Summary:** Pul defines latency as the gap from key release to results ready, prefetches on key down for the typed character plus every valid next character, renders on key up, and measures his own p99 budget at 121 ms across 100 typed domain names. The head of the index is an in-memory trie over the Tranco top one million with the top 8 suggestions precomputed per prefix, and the tail is CZDS gTLD zone data, sorted and delta-compressed into fixed-size blocks behind a 27 MB in-memory directory, holding 240 million names in about 2.5 GB on disk and answering with one binary search plus a linear scan of a 256-name block. Responses are bounded at about 5 kB, or 2.5 kB compressed, because only 38 characters are valid in a domain name, and load testing put the API alone near 2 ms at p50 and nginx plus API at 15 ms at p99 under 1.6k requests per second. The post is dated 2026-06-22 and reached the Hacker News front page on 2026-08-31, so it is an older write-up surfacing now rather than new work, and ccTLD zone data is unavailable so those names are covered only by the Tranco head.
- **Why it matters:** The post states where its own design fails, which is the network rather than the data structures, since a single server in Europe adds 100 to 200 ms for United States traffic and misses the budget at p99.
