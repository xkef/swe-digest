## Top stories

### OpenAI patched two Codex sandbox escapes, one reaching the developer host from the strictest mode

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://www.bleepingcomputer.com/news/security/researchers-escape-openai-codex-sandbox-to-run-commands-on-host/)
- **Blurb:** OpenAI fixed Heapjack and Overpatch in Codex Desktop 26.818.21641 and Codex CLI 0.149.0 after both escaped the sandbox.
- **Summary:** Researchers reported two escapes from the Codex sandbox. Heapjack broke out of read-only, the strictest mode, so opening an untrusted repository and asking a question was enough to run commands on the developer machine with no approval prompt. OpenAI fixed Heapjack in Codex Desktop build 26.818.21641 and Overpatch in Codex CLI 0.149.0, and advises users update to those versions or later.
- **Why it matters:** Both bugs put the enforcement mechanism inside the boundary it was enforcing, so reading an untrusted repository was sufficient for host command execution.
- **Follow-up:** Continues the coding-agent sandbox escape thread. OpenAI marked the July 2026 Pillar Security report informational and configuration-dependent, and fixed these two within eight days.

### Malicious npm package indexed-btree hides its loader in runtime code

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://www.bleepingcomputer.com/news/security/malicious-npm-packages-evade-install-script-defenses-at-runtime/)
- **Blurb:** The npm package indexed-btree hides its loader inside BTree.prototype.set(), which fires only when an application passes a specific key.
- **Summary:** Checkmarx reports that `indexed-btree` impersonates the legitimate `sorted-btree` library with a fabricated commit history and a curated developer account, and that it reached 2 million weekly downloads. The loader sits inside the library's own `BTree.prototype.set()` method and executes at runtime when the application calls it with a specific key value, so no install script runs. Checkmarx found nine further linked packages, now removed from npm: btree-core (1,951,274 downloads), btree-leaderboard (493,685), btree-range-store (468,092), ordered-kv-index (448,184), sliding-score-window (448,024), btree-time-index (425,312), priority-slot-queue (402,860), btree-lru-cache (372,185), and neighbor-key-map (366,019).
- **Why it matters:** The placement defeats the lifecycle-script approval npm shipped in June 2026, so install-time scanning alone no longer establishes that a dependency is clean.
- **Follow-up:** The stated remediation is that anyone who installed any of these packages rotates all secrets and restores the development environment from a safe backup. Open question is whether npm or the major scanners add runtime-path analysis.

### Google published AX, a Kubernetes-shaped orchestrator for agent workloads

- **Category:** Agentic coding
- **Status:** confirmed
- **Sources:** [primary](https://github.com/google/ax), [discussion](https://news.ycombinator.com/item?id=49780797)
- **Blurb:** Google published AX, which models agent workloads as Kubernetes-shaped Task, Workspace, Gateway, and Model resources.
- **Summary:** The README defines four declarative API kinds: Task (an isolated sandbox with CPU and memory limits), Workspace (pre-wired Git repositories, MCP servers, and skill packages), Gateway (outbound traffic locked to an explicit host allowlist), and Model (which LLM the platform itself uses, with credentials from a Kubernetes secret). Suspend and resume are CLI verbs rather than primitives. The project states that major breaking changes are expected before a stable release.
- **Why it matters:** It treats agents as a distinct workload class, moving sandboxing, egress control, and model credentials into the scheduling layer rather than leaving each agent runtime to implement them.
- **Follow-up:** Whether AX reaches a stable release and whether the primitives hold across agent runtimes other than Google's.

### Portainer 3.0 directs new capability work to Kubernetes and freezes the Docker feature set

- **Category:** Infrastructure
- **Status:** confirmed
- **Sources:** [primary](https://www.portainer.io/blog/the-docker-api-ceiling)
- **Blurb:** Portainer 3.0 sends new capability work to Kubernetes only and freezes the Docker feature set at today's scope.
- **Summary:** Portainer states that the Docker Engine API exposes no primitives to scope API access below root on the host. GPU scheduling, workload sandboxing, and fine-grained authorization will therefore land only for Kubernetes users.
- **Why it matters:** Teams standardized on Docker Engine through Portainer will not receive the new authorization and scheduling features without moving to Kubernetes.

### Dragonfly 2.0 released with lower connection and serialization overhead

- **Category:** Infrastructure
- **Status:** confirmed
- **Sources:** [primary](https://www.phoronix.com/news/Dragonfly-2.0-Released)
- **Blurb:** Dragonfly 2.0 cuts connection and serialization overhead, adds Valkey 9 RDB loading, and stays on BSL 1.1.
- **Summary:** The release reduces per-connection and serialization overhead, adds loading of Valkey 9 RDB files, and makes defragmentation limits configurable. Dragonfly remains under the Business Source License 1.1 rather than an open-source license.
- **Why it matters:** Valkey 9 RDB loading removes a migration step for operators moving off Redis or Valkey, with the license terms unchanged.
