## Top stories

### OpenAI patched two Codex sandbox escapes, one reaching the developer host from the strictest mode

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://www.bleepingcomputer.com/news/security/researchers-escape-openai-codex-sandbox-to-run-commands-on-host/)
- **Blurb:** OpenAI fixed Heapjack and Overpatch in Codex Desktop 26.818.21641 and Codex CLI 0.149.0 after both escaped the sandbox.
- **Summary:** Oren Yomtov of Accomplish AI reported two escapes from the Codex sandbox on 2026-08-12 and states OpenAI resolved both within eight days of that report. Heapjack broke out of read-only, the strictest mode, so opening an untrusted repository and asking a question was enough to run commands on the developer machine with no approval prompt. The report credits the fixes to Codex Desktop build 26.818.21641 and Codex CLI 0.149.0 and advises updating to those versions or later, while OpenAI's quoted statement says only that it addressed both issues in August.
- **Why it matters:** Both bugs put the enforcement mechanism inside the boundary it was enforcing, so reading an untrusted repository was sufficient for host command execution, continuing the coding-agent sandbox escape thread.
- **Follow-up:** Whether OpenAI publishes an advisory or CVE identifier for Heapjack and Overpatch.

### Malicious npm package indexed-btree hides its loader in runtime code

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://www.bleepingcomputer.com/news/security/malicious-npm-packages-evade-install-script-defenses-at-runtime/)
- **Blurb:** The npm package indexed-btree hides its loader inside BTree.prototype.set(), which fires only when an application passes a specific key.
- **Summary:** Checkmarx reports that `indexed-btree` impersonates the legitimate `sorted-btree` library with a fabricated commit history and a curated developer account, and that it reached 2 million weekly downloads. The loader sits inside the library's own `BTree.prototype.set()` method and executes at runtime when the application calls it with a specific key value, so no install script runs. Once triggered it collects architecture, hostname, CPU, memory, and uptime, exfiltrates through hardcoded Slack and Telegram channels, and polls an Ethereum Sepolia smart contract for command and control, using an X25519 key exchange to derive an AES key for a second-stage payload, and it can delete its files and remove the trigger to wipe traces. Checkmarx found nine further linked packages, now removed from npm: btree-core (1,951,274 downloads), btree-leaderboard (493,685), btree-range-store (468,092), ordered-kv-index (448,184), sliding-score-window (448,024), btree-time-index (425,312), priority-slot-queue (402,860), btree-lru-cache (372,185), and neighbor-key-map (366,019). The reporting names no affected version ranges for `indexed-btree` or the nine linked packages, so the stated remediation, that anyone who installed any of them rotates all secrets and restores the development environment from a safe backup, applies to any installed version.
- **Why it matters:** The placement defeats the lifecycle-script approval npm shipped in June 2026, so install-time scanning alone no longer establishes that a dependency is clean.
- **Follow-up:** Whether npm or the major scanners add runtime-path analysis.

### Brevo supply-chain attack rewrote scripts at the Cloudflare edge from a hardcoded API key

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://www.bleepingcomputer.com/news/security/brevo-supply-chain-attack-injected-clickfix-scripts-on-customer-sites/)
- **Blurb:** Attackers used a hardcoded Cloudflare API key to add a Worker that rewrote Brevo's customer-facing scripts at the edge.
- **Summary:** Brevo states the attackers held a long-lived Cloudflare API key with full account permissions that was hardcoded in application source code, and used it to create a Cloudflare Worker that rewrote responses at the CDN edge on 2026-09-14 between 16:07 and 20:30 UTC. The Worker stripped Content-Security-Policy headers while origin servers and files stayed unmodified, so integrity checks against the origin did not detect the change. It altered the Brevo forms script, the Conversations widget, and the SDK loader that customers embed on their own sites, which Sansec reports may have reached up to 100,000 websites. On WordPress sites the injected script checked whether the visitor was a logged-in administrator and attempted to install a backdoor plugin named Web Media Optimizer, which hides itself from the plugin list, copies itself into the must-use plugins directory, and carries a hardcoded key granting an administrator session without the password.
- **Why it matters:** The edge sat above every artifact the customer could verify, so a stolen CDN credential produced a script substitution that file and origin integrity checks could not see, and any WordPress administrator who browsed an affected site while logged in on 2026-09-14 has plugins installed that day and administrator passwords to audit.
- **Follow-up:** Whether Brevo or Sansec publishes a confirmed count of affected sites, which currently stands only as an upper estimate.

### Google published AX, a Kubernetes-shaped orchestrator for agent workloads

- **Category:** Agentic coding
- **Status:** confirmed
- **Sources:** [primary](https://github.com/google/ax), [discussion](https://news.ycombinator.com/item?id=49780797)
- **Blurb:** Google published AX, which models agent workloads as Kubernetes-shaped Task, Workspace, Gateway, and Model resources.
- **Summary:** The README defines four declarative API kinds: Task (an isolated sandbox with CPU and memory limits), Workspace (pre-wired Git repositories, MCP servers, and skill packages), Gateway (outbound traffic locked to an explicit host allowlist), and Model (which LLM the platform itself uses, with credentials from a Kubernetes secret). Suspend and resume are CLI verbs rather than primitives. The project states that major breaking changes are expected before a stable release.
- **Why it matters:** It treats agents as a distinct workload class, moving sandboxing, egress control, and model credentials into the scheduling layer rather than leaving each agent runtime to implement them.
- **Follow-up:** Whether AX reaches a stable release and whether the primitives hold across agent runtimes other than Google's.

### A widely discussed argument that MCP should be retired in favour of CLIs and HTTP APIs

- **Category:** Agentic coding
- **Status:** discussion
- **Sources:** [primary](https://maharship.com/blog/why-mcp-was-always-a-bad-idea/), [discussion](https://news.ycombinator.com/item?id=49779329)
- **Blurb:** A practitioner post argues MCP is obsolete because models now read CLI help text and call documented HTTP APIs.

- **Why it matters:** The argument reframes agent tool access as an HTTP content-negotiation problem, which would move the work from server authors to documentation and API owners.
- **Follow-up:** One practitioner's argument, not a project decision. Open question is whether any agent runtime adopts the content-negotiation path.

## Security

### Encrypted npm payload unlocks only from one specific derived value

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://safedep.io/mathmain-encrypted-loader/), [discussion](https://news.ycombinator.com/item?id=49791378)
- **Blurb:** SafeDep found npm packages whose payload decrypts only from one derived value, the JSON form of an LU lower factor.
- **Summary:** SafeDep reports five versions across the packages `mathmain`, `mathsbase`, and `math-universe` carrying an encrypted loader whose key is never present in the registry copy, and enumerates the exact affected versions with archive SHA-256 hashes in an indicators-of-compromise table, which could not be read from this environment because the fetch path renders package-and-version pairs as placeholders. The key is one specific derived value, the JSON form of the LU lower factor, which more than one caller input produces, and SafeDep states the Pascal matrix is not the only trigger. Decrypted, the payload is a remote access implant that polls Slack `conversations.history` every 10 seconds and runs operator messages as shell commands on the host through `execSync` or `spawn`, with a bundled `ethers` copy reading a Base Sepolia contract and reporting to Slack and `api.telegram.org`. SafeDep reports download totals of 605,157 for `mathmain`, 1,923,059 for `mathsbase`, and 569,730 for `math-universe` between 2026-09-12 and 2026-09-18, but also states that npm reported zero downloads registry-wide for 2026-09-17, that the packages have no public dependents and almost no jsDelivr traffic, and that no caller of the trigger was found in public code. This report and the Checkmarx report on `indexed-btree` in Top stories, both published on 2026-09-21, describe near-identical mechanics, hardcoded Slack and Telegram channels, an Ethereum testnet contract polled for command and control, an X25519 exchange deriving an AES key, and the trigger placed in ordinary runtime library behaviour rather than an install script, though neither report claims a shared actor.
- **Why it matters:** The registry copy never contains the decryption key, so neither static scanning nor SafeDep's own brute force, 16,922 candidate passwords against the filename blob and 533 against all five blobs, reached the payload until JFrog supplied the trigger input, and the loader is absent from the GitHub repositories the packages link, so the mechanism is confirmed while the exposure is not.
- **Follow-up:** Whether any real dependent is found that calls the trigger, which is what would turn this from a technique into an incident.

### Fake GitHub repositories push the Rapuncel infostealer with a signed kernel driver that kills 145 security products

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://www.bleepingcomputer.com/news/security/fake-lastpass-authenticator-github-repos-push-new-rapuncel-infostealer/)
- **Blurb:** SEO-optimized fake GitHub repos deliver the Rapuncel infostealer with a signed driver that kills 145 security tools.
- **Summary:** LastPass and Delphos Labs published the campaign report on 2026-09-18, covering SEO-optimized GitHub repositories that impersonate LastPass and at least 39 other companies to deliver a previously undocumented infostealer. The archives are inflated to as much as 148MB to evade scanning, and the installer is a renamed copy of the legitimate Visual Studio CoreCLR debugger `vsdbg.exe` configured to sideload a malicious `vsdbg.dll`. It drops the `Alinubx.sys` kernel driver, disguised as an NVIDIA component named `nvfsflt64.sys` and registered as the NvFsFilter service, which terminates a hardcoded list of 145 antivirus and EDR processes, and LastPass states the driver calls `ObOpenObjectByPointer` with AccessMode set to KernelMode, bypassing the user-mode access check and defeating Protected Process Light.
- **Why it matters:** Developers searching for tooling are the targeted population and a GitHub repository is the lure, while the driver is signed through Microsoft's Windows Hardware Compatibility Publisher chain and absent from Microsoft's vulnerable driver blocklist, so the kill list runs with a valid signature on a default install.
- **Follow-up:** Whether Microsoft adds `Alinubx.sys` to its vulnerable driver blocklist.

## Languages and runtimes

### Cloudflare marks Python Workers generally available and lands PEP 783 for Python on WebAssembly

- **Category:** Languages
- **Status:** confirmed
- **Sources:** [primary](https://blog.cloudflare.com/python-workers-ga/), [discussion](https://news.ycombinator.com/item?id=49787142)
- **Blurb:** Cloudflare made Python Workers generally available and landed PEP 783, which standardizes the PyEmscripten platform.
- **Summary:** Cloudflare states Python Workers bindings now convert types inside the runtime and SDK, so a call such as `env.QUEUE.send` on a Python dictionary no longer needs `pyodide.ffi.to_js` glue. The `workers.asgi` and `workers.wsgi` connectors run FastAPI, Django, Flask, and any other WSGI or ASGI framework, with the Workers platform acting as the web server rather than uvicorn or gunicorn. Cloudflare implemented socket system calls over the Workers connect API, which is what makes database drivers such as aiomysql and asyncpg work, because POSIX networking syscalls are normally stubs inside a WebAssembly sandbox.
- **Why it matters:** PEP 783 standardizes the PyEmscripten platform after more than a year of discussion, so maintainers can publish cross-compiled WebAssembly wheels for every environment that implements it rather than for one vendor.
