### Java 27 reaches general availability with G1 as the default collector in all environments and compact object headers on by default

- **Category:** Languages
- **Status:** confirmed
- **Sources:** [primary](https://mail.openjdk.org/archives/list/announce@openjdk.org/thread/ORGGLMN75HFEWP7YL3ZLGHLYHVIBJDYT/), [release page](https://openjdk.org/projects/jdk/27/), [discussion](https://news.ycombinator.com/item?id=49712041)
- **Blurb:** Mark Reinhold announced JDK 27 as generally available on 2026-09-15, shipping nine JEPs including post-quantum TLS key exchange.
- **Summary:** Mark Reinhold announced JDK 27, the reference implementation of Java 27, as Generally Available on 2026-09-15, stating that build 35 shipped as the second release candidate on 2026-08-20, that no P1 bugs have been reported since, and that build 35 is therefore the GA build. GPL-licensed OpenJDK builds are at jdk.java.net/27. The release carries nine JEPs: 523 makes G1 the default garbage collector in all environments, 534 turns on compact object headers by default, 527 adds post-quantum hybrid key exchange for TLS 1.3, 536 adds JFR in-process data redaction, and the remaining five are previews or incubators, namely 531 lazy constants, 532 primitive types in patterns, 533 structured concurrency, 537 the Vector API and 538 PEM encodings of cryptographic objects.
- **Why it matters:** Two of the nine JEPs change runtime behaviour with no code change on the upgrading side, so collector choice and heap footprint move on upgrade rather than on opt-in.
- **Follow-up:** Track reports of heap footprint and pause-time changes from deployments that were not previously running G1.

## ML research

### Sakana AI reports training 1000-layer networks without backpropagation using layer-local predictive coding

- **Category:** ML research
- **Status:** developing
- **Sources:** [primary](https://pub.sakana.ai/pc-alm/), [paper](https://arxiv.org/abs/2605.31022), [code](https://github.com/SakanaAI/pc-alm), [discussion](https://news.ycombinator.com/item?id=49701182)
- **Blurb:** Sakana AI reports training 1000-layer networks with layer-local predictive coding and no backpropagation pass.
- **Summary:** Sakana AI describes PC-ALM, a layer-local predictive coding method it reports trains networks of 1000 layers without a backpropagation pass, which the authors claim is the first layer-local method to reach that depth. The 1000-layer result is reported on MNIST only, at width 32, in residual MLPs, while CIFAR-10 and Tiny ImageNet appear as ResNet-18 comparisons against standard predictive coding at ordinary depth. Both the 1000-layer result and the first-layer-local claim appear only in the write-up, which carries a September 2026 date: the preprint it cites, arXiv 2605.31022 by Seely and Gould submitted 2026-05-29, states it analyzes PC-ALM in nonlinear predictive coding networks up to depth 128. No third party has reproduced the numbers.
- **Why it matters:** Every layer in PC-ALM communicates only with its neighbours, so the result bears on distributed and neuromorphic training hardware where backpropagation's global forward-then-backward ordering is the expensive constraint.
- **Follow-up:** Track an independent reproduction of the 1000-layer result outside the authors' benchmark set.

### An ICML paper reports that discounting correlated LLM judges beats weighted majority vote by 9 to 14 percent

- **Category:** Paper
- **Status:** confirmed
- **Sources:** [primary](https://www.amazon.science/blog/when-llm-judges-agree-should-we-believe-them), [discussion](https://news.ycombinator.com/item?id=49699590)
- **Blurb:** Amazon researchers report a judge-aggregation method that beats weighted majority vote by 9 to 14 percent on existing logs.
- **Summary:** An Amazon Science post dated 2026-08-26 describes a peer-reviewed paper presented at ICML 2026 on aggregating the votes of multiple LLM judges. The method discounts judges whose errors are correlated, and the authors report a 9 to 14 percent improvement over weighted majority vote. The correlation estimate is derived from evaluation logs rather than from new labelled data.
- **Why it matters:** Teams that add judges to a panel to reduce noise may be adding correlated votes instead, and the method measures that from evaluation logs those teams already collect.

### A preprint claims a proof of the k-server conjecture, arguing the work function algorithm is k-competitive on every metric space

- **Category:** Paper
- **Status:** developing
- **Sources:** [primary](https://arxiv.org/abs/2609.15979), [discussion](https://news.ycombinator.com/item?id=49709129)
- **Blurb:** Three authors post an arXiv preprint claiming a proof that the work function algorithm is k-competitive on every metric space.
- **Summary:** Christian Coester, Elias Koutsoupias and Marek Zbysinski submitted the preprint to arXiv cs.DS on 2026-09-14, stating a proof of the k-server conjecture, which holds that a deterministic online algorithm can reach competitive ratio k on every metric space, by showing the work function algorithm satisfies that bound. The proof represents the work function as a matrix encoding all feasible paths to a configuration, so each work function value is the determinant of k columns and a request arrival updates the representation by a change of basis and a row replacement, with the amortized analysis resting on a potential function over a larger matrix. The preprint is not peer reviewed and no third party has verified it.
- **Why it matters:** The k-server problem generalizes paging and cache eviction, so the ratio it settles is the worst-case bound on the online decision an eviction policy makes.
- **Follow-up:** Track a referee report or an independent verification of the proof.

- **Category:** Outage
- **Status:** confirmed
- **Sources:** [primary](https://status.redhat.com/incidents/0g8rsg3tbjpz), [discussion](https://news.ycombinator.com/item?id=49705394)
- **Blurb:** Red Hat's Quay.io refused pushes from 2026-09-14 13:34 UTC and served pulls only from 15:35 UTC until read/write returned.
- **Summary:** Red Hat's status page opens the incident at 2026-09-14 13:34 UTC as degraded performance on the Quay.io push and pull API, and the 14:02 and 14:04 UTC updates state Red Hat identified the cause of the image pull failures. Read-only mode, described as only pulls being served, began at 15:35 UTC, and the 2026-09-15 04:05 UTC Monitoring update states the fix has been deployed and Quay.io is serving read/write requests. Red Hat marked the incident Resolved at 2026-09-15 09:15 UTC, states the registry has been operational since 05:00 UTC that day, states the recovery required updating three affected database tables, and gives the cause in its own words as an underlying issue related to database scaling that was resolved successfully without any data loss. The same resolution note states Clair vulnerability scanning remains on maintenance until further notice.
- **Why it matters:** A registry that answers pulls but refuses pushes keeps deployments running while release pipelines stall, so this class of incident surfaces in build jobs well before anything user-facing breaks.

### An eBPF security agent caches policy lookups per inode and cuts benchmark kernel cycles from 28 billion to 3.03 billion

- **Category:** Linux/Kernel
- **Status:** confirmed
- **Sources:** [primary](https://nathannaveen.dev/posts/dropping-ebpf-cpu-cost-by-90/), [code](https://github.com/bomfather/agent), [discussion](https://news.ycombinator.com/item?id=49697477)
- **Blurb:** Per-inode caching of policy lookups cut the agent's benchmark kernel cycles by about 90 percent, from 28 to 3.03 billion.
- **Summary:** A post dated 2026-09-11 describes caching policy lookups per inode inside an eBPF security agent. The benchmark opened the same file 200,000 times, and the author reports kernel cycles falling from 28 billion to 3.03 billion. Hardlinks take a fallback path outside the cache, which the author describes as choosing accuracy over cache coverage.
- **Why it matters:** The cache lives inside the agent, so an operator collects the reported reduction from an upgrade alone without rewriting a single policy.
