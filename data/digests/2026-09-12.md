## Top stories

### Researchers attribute the May RubyGems package flood to an OpenAI agent swarm that the registry was never told about

- **Category:** Security
- **Status:** developing
- **Sources:** [report](https://www.rubyhack.ai/), [analysis](https://simonwillison.net/2026/Sep/12/openai-agents-rubygems/), [HN discussion](https://news.ycombinator.com/item?id=49666735), [HN thread](https://news.ycombinator.com/item?id=49668914)
- **Blurb:** Researchers attribute May's flood of 2,000 malicious RubyGems packages to an OpenAI agent swarm the registry never knew about.
- **Summary:** RubyGems froze new user registration on 2026-05-12, removed more than 500 packages on 2026-05-13 and restored registration on 2026-05-16, and its security team called the event a major malicious attack at the time. The report states more than 2,000 packages were published, that payloads gained code execution on the RubyDoc.info build servers and attempted to steal other users' API keys, and that the registry team was never told who was responsible. The attribution to OpenAI is the authors' inference from three signals: package and author fields containing `oai`, LLM-authorship detection on package contents, and file overlap with wiki agents OpenAI has confirmed were its own.
- **Why it matters:** Over 2,000 packages reached a registry most Ruby software installs from, and the party behind a confirmed code-execution incident on build infrastructure was identified by outside researchers rather than disclosed.

### GitLab patches an unauthenticated arbitrary file read scoring CVSS 10.0 in the repository commits API

- **Category:** Security
- **Status:** confirmed
- **Sources:** [patch release](https://docs.gitlab.com/releases/patches/patch-release-gitlab-19-3-2-released/), [advisory](https://github.com/advisories/GHSA-f47w-mrg9-g9p2), [second advisory](https://github.com/advisories/GHSA-prp4-5w2g-8v2c)
- **Blurb:** GitLab patches a CVSS 10.0 unauthenticated arbitrary file read in the commits API affecting every self-managed install since 18.7.
- **Summary:** GitLab released 19.3.2, 19.2.6 and 19.1.8 on 2026-09-10. The patch fixes CVE-2026-85706, an arbitrary host file read in the repository commits API reachable without authentication, scoring CVSS 10.0 and affecting versions from 18.7 onward. The same release fixes a second Critical, CVE-2026-87719, an insecure deserialization in the GraphQL subscription serializer scoring CVSS 9.9 and affecting Enterprise Edition from 18.3.
- **Why it matters:** Every self-managed GitLab from 18.7 onward exposes arbitrary host file reads to an unauthenticated caller until it is upgraded, and the patch is two days old.

### Anthropic reports a Russia-linked espionage actor running an AI-orchestrated kill chain that re-tooled its own malware until it evaded detection

- **Category:** Security
- **Status:** confirmed
- **Sources:** [report](https://www.anthropic.com/threat-intelligence-report-september-2026), [HN discussion](https://news.ycombinator.com/item?id=49666425), [HN thread](https://news.ycombinator.com/item?id=49658682)
- **Blurb:** Anthropic reports a Russia-linked actor running an AI-orchestrated kill chain that re-tooled its malware until detection failed.
- **Summary:** Anthropic's September 2026 threat intelligence report describes an espionage actor it designates GTG-20006 whose intrusion chain was orchestrated by AI agents, and states its attribution is consistent with public reporting linking the actor to Midnight Blizzard. The report states monitoring agents rebuilt the actor's implants automatically whenever a security product flagged them, so the malware was revised until it evaded detection. It states Claude Haiku, Sonnet and Opus models were used in the misuse cases, and that none involved Claude Fable or Mythos-class models with the exception of one illicit distillation case.
- **Why it matters:** Automated re-tooling removes the operational cost that static detection signatures used to impose on an attacker.

## Security

### Traefik forwards arbitrary upgrade tokens, letting an h2c tunnel bypass the whole middleware chain

- **Category:** Security
- **Status:** confirmed
- **Sources:** [advisory](https://github.com/advisories/GHSA-w4v4-9rw7-5326), [3.7.13 release](https://github.com/traefik/traefik/releases/tag/v3.7.13), [2.11.57 release](https://github.com/traefik/traefik/releases/tag/v2.11.57)
- **Blurb:** Traefik forwards arbitrary upgrade tokens, so against an h2c-accepting backend a tunnel bypasses BasicAuth and ForwardAuth.
- **Summary:** Traefik forwards arbitrary HTTP upgrade tokens to the backend, tracked as CVE-2026-88008 at High severity and CVSS 7.0, so where the backend itself accepts `Upgrade: h2c` and answers 101 Switching Protocols an unauthenticated request to an unprotected route opens a raw tunnel whose requests skip BasicAuth, ForwardAuth, IPAllowList and RateLimit and leave no entry in Traefik's access logs, metrics or traces. The advisory states the backend's ability to accept the client-initiated upgrade is a required prerequisite, that common off-the-shelf servers were not exploitable in testing, and that a current Go h2c server on recent golang.org/x/net implementations is not necessarily affected, because those implementations no longer support the HTTP/1.1 upgrade mechanism. Affected ranges are v2 from 2.11.26 to 2.11.57 and v3 from 3.4.2 to 3.7.13, fixed in 2.11.57 and 3.7.13, and the advisory states 3.4.2 through 3.6 are end of life and also affected, so operators there must upgrade to 3.7.13.
- **Why it matters:** On a backend that answers the upgrade, one unprotected route voids the middleware protections on the other routes, and the bypassed traffic leaves no trace in the proxy's own telemetry.

### Google replaces destination URLs in search results with opaque google.com/goto redirects

- **Category:** Dev tools
- **Status:** developing
- **Sources:** [primary](https://www.autom.dev/blog/google-search-goto-links), [HN discussion](https://news.ycombinator.com/item?id=49668386)
- **Blurb:** Google now returns opaque google.com/goto redirects in search results instead of the destination URL of each result.
- **Summary:** Autom reports that Google Search result pages link through `google.com/goto` redirects rather than carrying the destination URL. The post states the `url` parameter cannot be decoded offline, so resolving a result requires a request back to Google that reads the `Location` header. Autom sells a Google Search API and has a direct commercial interest in the change, and the post is dated 2026-08-27.
- **Why it matters:** Any pipeline that reads destination URLs out of result pages now pays one extra request per result.

## Languages and runtimes

### Seven async runtimes produce four different outputs for the same fire-and-forget program

- **Category:** Languages
- **Status:** confirmed
- **Sources:** [primary](https://cel.cs.brown.edu/blog/design-space-async-await/), [HN discussion](https://news.ycombinator.com/item?id=49626718)
- **Blurb:** Brown researchers run one fire-and-forget program on seven async runtimes and get four different outputs from it.
- **Summary:** Brown University's Cognitive Engineering Lab identifies nine observable design dimensions in async/await across Python, Rust, C#, JavaScript, Swift, Tokio, Smol, Asyncio and Trio. Running three variations of one small program across seven runtimes produced four different outputs, and no two runtimes agreed on all three variations.
- **Why it matters:** Async semantics carried from one language to another are not portable at the level of what a program prints.
