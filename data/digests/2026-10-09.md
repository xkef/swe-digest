### One unauthenticated POST stalls a react-server-dom app with a reachable server action, patched five months ago in 19.0.6, 19.1.7 and 19.2.6

- **Category:** Security
- **Status:** confirmed
- **Sources:** [advisory](https://github.com/advisories/GHSA-rv78-f8rc-xrxh), [writeup](https://simonkoeck.com/writeups/react-rsc-formdata-event-loop-dos), [discussion](https://news.ycombinator.com/item?id=50020073)
- **Blurb:** One unauthenticated POST stalls a react-server-dom app for seconds per request, fixed quietly in May in three releases.
- **Summary:** The advisory, CVE-2026-23870, states only that specially crafted HTTP requests to server function endpoints can cause out-of-memory exceptions or excessive CPU usage, and it names react-server-dom-webpack, react-server-dom-turbopack and react-server-dom-parcel at >= 19.0.0 < 19.0.6, >= 19.1.0 < 19.1.7 and >= 19.2.0 < 19.2.6. The mechanism comes from the researcher writeup rather than the advisory: a crafted request makes the server rebuild form data in a loop that blocks the event loop, and the only input needed is a server action ID that the app prints in its own page HTML. - **Why it matters:** The writeup states the rebuild runs before any login, CSRF or origin check, so an app on an affected version with at least one server action anywhere it can be reached gains nothing from its own auth configuration.
