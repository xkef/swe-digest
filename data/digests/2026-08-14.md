### Christopher Domas releases a technique that flips one DRAM controller bit to reach PSP memory, SMRAM, C6 and microcode on AMD Family 16h

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://github.com/xoreaxeaxeax/skitter-creek-bath-salts), [discussion](https://news.ycombinator.com/item?id=49286341)
- **Summary:** The technique rewrites the final address translation stage in the memory controller on AMD Family 16h, the last generation whose datasheets document those DRAM controller translation registers. It reaches PSP memory, SMRAM, C6 and microcode. It presumes the attacker can already write MMIO, so it breaks the boundaries above ring 0 rather than granting ring 0.
- **Why it matters:** Every platform memory protection sits above the memory controller and guards physical addresses rather than DRAM coordinates, so rewriting the final translation stage reaches protected carveouts without tripping any of them.

## AI

### Anthropic's policy page permits training classifiers on Claude outputs and prohibits training competing general-purpose models

- **Category:** AI
- **Status:** confirmed
- **Sources:** [primary](https://support.claude.com/en/articles/12326764-can-i-use-my-outputs-to-train-an-ai-model), [discussion](https://news.ycombinator.com/item?id=49283563)
- **Summary:** The page draws the line by what the trained model is rather than by how the outputs were obtained. Sentiment, categorization, summarization, extraction, semantic search and anomaly detection models are permitted. Using outputs as training targets for a general-purpose or open-ended text model is not.
- **Why it matters:** Teams building classifiers on Claude outputs have a stated permission, while teams distilling a general-purpose model do not.

## Linux and kernel

### LWN covers a proposed Linux process-builder API that assembles a process from an empty pidfd instead of forking

- **Category:** Linux/Kernel
- **Status:** developing
- **Sources:** [primary](https://lwn.net/Articles/1086330/), [discussion](https://news.ycombinator.com/item?id=49293745)
- **Summary:** The series would give Linux a native path for posix_spawn that skips copying the parent, assembling a process from an empty pidfd. It is a proof of concept that still calls vfork internally. It had drawn one review comment since it was posted on 2026-07-16.
- **Why it matters:** A native process-builder path would let posix_spawn avoid the copy-on-write cost of forking a large parent.

### An open systemd issue reports journald doing about 50 IOPS to write two log lines per second

- **Category:** Linux/Kernel
- **Status:** developing
- **Sources:** [primary](https://github.com/systemd/systemd/issues/40262), [discussion](https://news.ycombinator.com/item?id=49290215)
- **Summary:** The reporter measures write amplification at the VM block layer rather than in iotop, which is what closed the earlier report. The issue records about 50 IOPS to write two log lines per second.
- **Why it matters:** journald is the default log path on the distributions most servers run, so write amplification there affects storage-constrained hosts broadly.

## Infrastructure

### Bluesky launches Protocol Services with Jetstream v2, adding network replay and requiring an API token for archive reads

- **Category:** Infrastructure
- **Status:** confirmed
- **Sources:** [primary](https://atproto.com/blog/introducing-bluesky-protocol-services), [discussion](https://news.ycombinator.com/item?id=49293324)
- **Summary:** Bluesky launched Protocol Services with Jetstream v2. Replay removes the need to backfill repositories locally before joining the live stream. Archive requests now require an API token, the first authentication requirement on the public Jetstream infrastructure, and the post states the live tail stays open and unauthenticated with no plans to change that.
- **Why it matters:** Replay lets a consumer join the live stream without a local backfill, and archive reads now require an API token.
