The published ledger records five corrections to the agents' own records: a YBaMnFeO5 hull distance of +13.7 meV/atom rather than +2.6, computed before competing phases finished and no longer at the edge of stability, an HSE06 run the run index marked converged whose exact-exchange loop had stopped early, two partly relaxed geometries, one truncated output, and a 2008 hybrid-functional paper by Middlemiss, Lawton and Wilson whose spin-resolved plot already shows the same-spin band edges, which narrows the novelty claim.
- **Why it matters:** The published inputs, raw outputs and ledger made five errors in the agents' own records findable, which is the part of an agent-science claim a reader can check.

### Malicious @subql/common 5.8.3 stole AWS, GitHub, Kubernetes and Vault credentials after a CI compromise

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://flatt.tech/research/posts/subql-common-npm-supply-chain-attack/)
- **Blurb:** A malicious @subql/common 5.8.3 published through GitHub Actions OIDC stole AWS, GitHub, Kubernetes and Vault credentials.
- **Summary:** Flatt Security reports that @subql/common 5.8.3 was published at 11:56 UTC on 2026-10-05 from a compromised CI pipeline, after an unsigned commit rewrote publish.yml, and was removed from npm about 50 minutes later at roughly 12:46 UTC, with 5.8.2 the latest known safe version. The package shipped through npm's GitHub Actions OIDC Trusted Publisher, so the npm publisher field read as GitHub Actions and provenance did not separate the malicious version from a legitimate release. The payload harvested AWS, GitHub, SSH, npm, Docker, Kubernetes and Vault credentials, read coding-agent configuration files including `~/.claude.json`, `~/.claude/mcp.json` and `.kiro/settings/mcp.json`, and is not stopped by disabling lifecycle scripts, because its warm() entry point also fires on `require('@subql/common')`.
- **Why it matters:** Anyone who installed 5.8.3 has to rotate AWS, GitHub, SSH, npm, Docker, Kubernetes and Vault credentials and kill any lingering manifest-cache.js --warm process.
- **Follow-up:** Watch for npm or GitHub guidance on separating Trusted Publisher provenance from a compromised pipeline.

### Five cross-tenant elevation-of-privilege bugs in Azure API Connections reached other tenants' Key Vaults

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://binsec.no/posts/2026/10/one-root-case)
- **Blurb:** A researcher reports five Azure API Connections bugs that read other tenants' Key Vault secrets and SQL databases.
- **Summary:** A post dated 2026-10-02 reports five elevation-of-privilege bugs in Azure API Connections, each reaching API Connections held by other tenants. The common cause is that the Azure API Management instance holds rights to every API Connection regardless of which one a request names, so path traversal through DynamicInvoke, undocumented sibling endpoints such as DynamicList, or the host.api.RuntimeUrl parameter was enough. The post states that Microsoft fixed each report with input validation or endpoint blocking rather than changing the token exchange, and that one fix validated the runtime URL before path normalization and so did not hold.
- **Why it matters:** Fixes applied at the request surface rather than at the token exchange leave the same design fact available to the next variant.
- **Follow-up:** Watch for a further variant or for a change to how API Management obtains API Connection tokens.
