## Top stories

### A very long instruction keeps a core outside System Management Mode on one tested AMD Zen 3 part

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://github.com/xoreaxeaxeax/smiiiiiiiiiiiiiiii), [discussion](https://news.ycombinator.com/item?id=49245491)
- **Summary:** Christopher Domas published a proof of concept in which one long-running instruction keeps a core outside System Management Mode for about one second, breaking the rendezvous that SMM handlers rely on. The README states the demonstration is tuned for a Zen 3 Ryzen 7 5800H and uses a wide xmm load from MMIO at `0xfcc68860`, and that on any other part one should expect no divergence until the long instruction is retuned. He states that SMM time-of-check-to-time-of-use bugs were written off as needing a DMA-capable peripheral and physical access, counts over 100 CVEs in that class, and states there is probably no workable mitigation.
- **Why it matters:** The technique brings a bug class the author counts at over 100 CVEs, previously written off as needing a DMA-capable peripheral and physical access, into reach from software. The affected hardware range is not established beyond the single AMD Zen 3 part tested, and no affected microarchitecture list, firmware version range, or fix is stated, so the reach of the technique is open.
- **Follow-up:** Whether the technique reproduces on other microarchitectures, and any vendor or firmware response.

### An unreleased Claude research model raises a Riemann zeta lower bound from 41.6 percent to 67.2 percent

- **Category:** AI
- **Status:** confirmed
- **Sources:** [primary](https://www.anthropic.com/research/riemann-zeta), [discussion](https://news.ycombinator.com/item?id=49247070)
- **Summary:** Anthropic reports that an unreleased research model raised the lower bound on the fraction of zeros of the Riemann zeta function that lie on the critical line, from 41.6 percent to 67.2 percent. The result ships with a Lean formalization that passes the comparator validation tool. Levent Alpoge and Ralph Furman at Anthropic examined it, along with Brian Conrey and Dan Goldston outside the company.
- **Why it matters:** A machine-checked artifact plus named outside examiners is a stronger evidentiary standard than the prose proof PDFs that earlier AI-credited math claims shipped with.
- **Follow-up:** Independent review of the formalization, and whether the bound is accepted in the analytic number theory literature.

## AI

### Cactus releases Needle 2, a 45M-parameter tool-calling model in a 14MB binary under Apache 2.0

- **Category:** AI
- **Status:** confirmed
- **Sources:** [primary](https://cactuscompute.com/needle), [discussion](https://news.ycombinator.com/item?id=49246804)
- **Summary:** Cactus states Needle 2 is 45M parameters compressed to CQ2-bit, shipping as a single 14MB binary with a 28MB session RAM ceiling from a 256-token sliding attention window, which puts it on ESP32-S3 and Cortex-M class parts, with weights on Hugging Face under Apache 2.0. Reported speeds are 500 tokens per second decode on a Raspberry Pi 5 and 300 to 700 on sub-200-dollar phones. The evaluation names five public benchmarks (Google Mobile Actions, DroidCall, Seal-Tools in-domain and out-of-domain, BFCL v4 single-turn), scores them as ordered strict exact match, and states Needle numbers are measured end-to-end through the shipped engine at deployment precision while baselines run at f16 under vLLM.
- **Why it matters:** Tool calling at this footprint puts the routing decision on microcontroller-class hardware, though the numbers are vendor-run and not independently reproduced.
- **Follow-up:** Whether an independent party reproduces the benchmark scores or the on-device throughput.

### Docker's Sandboxes page describes per-agent microVM isolation and labels the product Experimental

- **Category:** Agentic coding
- **Status:** confirmed
- **Sources:** [primary](https://www.docker.com/products/docker-sandboxes/), [discussion](https://news.ycombinator.com/item?id=49239751)
- **Summary:** Docker's product page states each agent runs in a dedicated microVM with only the project workspace mounted, that the host is untouched, and that permissive execution is the default rather than an opt-in. It names Claude Code, Gemini CLI, Copilot CLI, Codex, OpenCode, and Kiro as supported out of the box, publishes install paths for a `sbx` binary on macOS, Windows, and Ubuntu, and states Docker Desktop is not required. The page carries no dated release announcement and this run found no matching launch post on Docker's blog, so what is recorded here is the page's own statement of scope and status rather than a ship date.
- **Why it matters:** Isolation for running an agent with permission prompts off is offered as vendor infrastructure rather than a per-team script, while the controls a team would need to constrain it are held behind a paid tier.
- **Follow-up:** Whether Sandboxes leaves Experimental, and whether network and filesystem policy stay behind the paid tier.

### Dan Luu's evals find the token-efficiency case for dynamic languages in coding agents does not survive non-trivial tasks

- **Category:** Agentic coding
- **Status:** discussion
- **Sources:** [primary](https://danluu.com/pl-tokens/), [discussion](https://news.ycombinator.com/item?id=49245936)
- **Summary:** The widely cited claim is that dynamically typed languages cost fewer tokens because they omit type declarations, with a stated 2.6x gap between C and Clojure and J at 70 tokens average, which Luu notes comes from Rosetta Code tasks solvable in tens of tokens. He runs two larger evals instead, a zstd decoder implemented from the RFC without tests and a modified Pandoc ProgramBench scored against holdout tests, and the dynamic cluster lands ahead at medium effort while the ultra effort result is mixed with several static languages among the best and obscure dense languages doing poorly. He documents a defect in one cited benchmark where a test executed a `../../minigit` path that did not exist, which is what caused the Rust and Haskell failures the benchmark's author read as evidence that difficult languages burden the model. A Go agent later symlinked that path to its own executable, so scoring on that broken test after the symlink measured the Go binary, and Luu notes the Rust scoring ran before it.
- **Why it matters:** Language choice for agent work is being argued from token counts measured on problems too small to separate the languages, and Luu reports the only durable signal as a weak to moderate positive correlation between language popularity and both correctness and cost.

## Apple platforms

### antirez publishes h3.c, a native Metal implementation of MiniMax-H3 video inference for Apple Silicon

- **Category:** Apple
- **Status:** confirmed
- **Sources:** [primary](https://github.com/antirez/h3.c), [discussion](https://news.ycombinator.com/item?id=49252179)
- **Summary:** The MIT-licensed repository, at 836 stars and 120 commits, implements prompt-to-video and audio, first and last frame conditioning, and ordered Ref2VA image, video, and audio references end to end in Metal. The README documents speed and quality as independent knobs with measured costs: a four-pass denoise took about 3.5 seconds on M5 Max against 26.4 seconds for a 29-pass reference, at 0.556 full-video SSIM on the fox test and 0.547 on an independent surfer test, and token reduction cut one profile from 16.69 to 12.60 seconds. It also records what failed, including tail-heavy schedules that produced woven texture and clipped colors, and the combination of 40 layers with reuse 3 plus token reduction that produced color ringing and ghosted limbs.
- **Why it matters:** Video inference runs on Apple Silicon through Metal directly, with the quality cost of each speedup measured against a reference rather than asserted.

## Engineering posts

### VectorWare compiles Rust portable SIMD to GPU warp instructions

- **Category:** Engineering post
- **Status:** confirmed
- **Sources:** [primary](https://www.vectorware.com/blog/simd-on-gpu/), [discussion](https://news.ycombinator.com/item?id=49247477)
- **Summary:** The post describes compiling Rust's `core::simd` to GPU warp instructions, mapping SIMD lanes onto warp lanes, reductions onto warp shuffles, and mask queries onto vote and ballot instructions. It states the mapping is one to one only when the vector width matches the hardware warp width, which is 32 lanes on NVIDIA.
- **Why it matters:** Portable SIMD code can target a GPU without a separate kernel language, at a cost that depends on matching the warp width.

- **Status:** confirmed
