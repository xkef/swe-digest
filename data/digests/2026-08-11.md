## Top stories

### A very long instruction keeps a core outside System Management Mode on one tested AMD Zen 3 part

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://github.com/xoreaxeaxeax/smiiiiiiiiiiiiiiii), [discussion](https://news.ycombinator.com/item?id=49245491)
- **Summary:** Christopher Domas published a proof of concept in which one long-running instruction keeps a core outside System Management Mode for about one second, breaking the rendezvous that SMM handlers rely on. The README states the demonstration is tuned for a Zen 3 Ryzen 7 5800H and uses a wide xmm load from MMIO at `0xfcc68860`, and that on any other part one should expect no divergence until the long instruction is retuned. He states that SMM time-of-check-to-time-of-use bugs were written off as needing a DMA-capable peripheral and physical access, counts over 100 CVEs in that class, and states there is probably no workable mitigation.
- **Why it matters:** The affected hardware range is not established beyond the single AMD Zen 3 part tested, and no affected microarchitecture list, firmware version range, or fix is stated, so the reach of the technique is open.
- **Follow-up:** Whether the technique reproduces on other microarchitectures, and any vendor or firmware response.

### An unreleased Claude research model raises a Riemann zeta lower bound from 41.6 percent to 67.2 percent

- **Category:** AI
- **Status:** confirmed
- **Sources:** [primary](https://www.anthropic.com/research/riemann-zeta), [discussion](https://news.ycombinator.com/item?id=49247070)
- **Summary:** Anthropic reports that an unreleased research model raised the lower bound on the fraction of zeros of the Riemann zeta function that lie on the critical line, from 41.6 percent to 67.2 percent. The result ships with a Lean formalization that passes the comparator validation tool. Levent Alpoge and Ralph Furman at Anthropic examined it, along with Brian Conrey and Dan Goldston outside the company.
- **Why it matters:** A machine-checked artifact plus named outside examiners is a stronger evidentiary standard than the prose proof PDFs that earlier AI-credited math claims shipped with.
- **Follow-up:** Independent review of the formalization, and whether the bound is accepted in the analytic number theory literature.

### Anthropic states models launched from 2026-08-02 will carry machine-readable marks in generated text

- **Category:** AI
- **Status:** developing
- **Sources:** [primary](https://support.claude.com/en/articles/16266773-how-claude-marks-ai-generated-content), [discussion](https://news.ycombinator.com/item?id=49250109)
- **Summary:** Anthropic's support article describes how it plans to put its EU AI Act Article 50(2) Code of Practice commitments into practice, and is written as forward commitments rather than as shipped behavior. It states that models launched in the EU on or after 2026-08-02 will support marking, that generated text will carry embedded watermarks, and that marking will apply worldwide rather than only in the EU. The products it lists as covered are the Claude Platform API, Claude, Claude Code, Claude Cowork, and Claude Tag, including access through AWS, Google Cloud, and Microsoft Foundry.
- **Why it matters:** Once the marking is in place, text a supported model generates carries an embedded mark wherever it is used, including output that passes through an application before reaching a reader.
- **Follow-up:** When marking is actually enabled per product, and whether the mark survives editing or reformatting.

### A foundation-model oracle finds 13 behavioral-change bugs in the Rope Python refactoring library

- **Category:** Paper
- **Status:** developing
- **Sources:** [primary](https://arxiv.org/abs/2608.09919)
- **Summary:** The authors use a foundation model as a test oracle to decide whether a refactoring preserves program behavior, and report 13 behavioral-change bugs found in the Rope Python refactoring library. They report 12 of their 13 issue reports accepted by Rope's developers.
- **Why it matters:** Rope backs refactoring in several Python editor integrations, so refactorings assumed to preserve behavior did not.

## Security

### Apple patches a network Screen Sharing authentication bypass in macOS Tahoe 26.6.1

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://support.apple.com/en-us/148170), [discussion](https://news.ycombinator.com/item?id=49247537)
- **Summary:** Apple's advisory for macOS Tahoe 26.6.1, released 2026-08-06, covers CVE-2026-65400 in Screen Sharing. Apple states an attacker on the network may be able to authenticate to Screen Sharing without valid credentials, scopes the entry as available for macOS Tahoe, and describes the fix as an authentication issue addressed with improved state management. Apple credits Alfredo Pesoli, via Bynario Atlas.
- **Why it matters:** Any Mac with Screen Sharing enabled on a shared network needs 26.6.1, and the advisory predates this digest by five days.

## Engineering posts

### VectorWare compiles Rust portable SIMD to GPU warp instructions

- **Category:** Engineering post
- **Status:** confirmed
- **Sources:** [primary](https://www.vectorware.com/blog/simd-on-gpu/), [discussion](https://news.ycombinator.com/item?id=49247477)
- **Summary:** The post describes compiling Rust's `core::simd` to GPU warp instructions, mapping SIMD lanes onto warp lanes, reductions onto warp shuffles, and mask queries onto vote and ballot instructions. It states the mapping is one to one only when the vector width matches the hardware warp width, which is 32 lanes on NVIDIA.
- **Why it matters:** Portable SIMD code can target a GPU without a separate kernel language, at a cost that depends on matching the warp width.

### The Illinois age-verification law discussed as putting Linux on the hook is Public Act 104-0664, effective 2028-01-01

- **Category:** Infrastructure
- **Status:** confirmed
- **Sources:** [primary](https://www.ilga.gov/Legislation/BillStatus?DocNum=5511&GAID=18&DocTypeID=HB&LegID=&SessionID=114), [discussion](https://news.ycombinator.com/item?id=49249150)
- **Summary:** A 297-point thread argued that an Illinois age-verification law obliges operating system providers, including Linux distributions. The ILGA record for HB 5511 shows that House Floor Amendment No. 1 replaced everything after the enacting clause with "covered manufacturer of an Internet-enabled device", and Senate Floor Amendment No. 2 replaced it again. The enacted act is Public Act 104-0664, effective 2028-01-01.
- **Comments:** The "operating system provider" wording HN commenters quote belongs to the introduced draft rather than to the act that was signed. This run could not resolve the public act full text at the legacy ILGA path, and the bill status page carries synopses rather than definitions, so whether a Linux distribution is a covered manufacturer is not established here.
- **Why it matters:** The obligation that reaches engineers is an age-bracket signal API between device makers and application operators, on a 2028 timetable.
- **Follow-up:** The enacted full text of Public Act 104-0664 and its definition of covered manufacturer.
