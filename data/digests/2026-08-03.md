## Top stories

### Arch Linux disables AUR package adoption and then all pushes after a wave of malicious takeovers of orphaned packages

- **Category:** Security
- **Status:** confirmed
- **Sources:** [aur-general announcement](https://lists.archlinux.org/archives/list/aur-general@lists.archlinux.org/message/YPJ3FQYJTJXXY3RUXCYLMHUKHLIUNVFF/), [aur-general archive](https://lists.archlinux.org/archives/list/aur-general@lists.archlinux.org/latest), [BleepingComputer report](https://www.bleepingcomputer.com/news/security/arch-linux-disables-aur-package-adoption-to-stop-malware-flood/), [HN discussion](https://news.ycombinator.com/item?id=49146238)
- **Summary:** The Arch Linux DevOps team announced on the aur-general mailing list that package adoption in the AUR was disabled on 2026-07-30, and then that all pushes to the AUR were disabled on 2026-08-01, after a wave of malicious takeovers of orphaned packages. The first-party announcement names neither the affected packages nor a count. BleepingComputer relays a community tracker putting the scale at roughly 200 packages, states that the figure is not independently confirmed, and no full list has been published. The reported malware behaviour is a poisoned PKGBUILD build step whose second stage collects SSH keys, cloud and AI service API keys, and password manager data, and that behaviour comes from third-party analysis rather than from Arch.
- **Why it matters:** An AUR helper builds and runs PKGBUILD code as the invoking user, so a poisoned build step runs on the developer's own machine, and the reported second stage takes credentials from exactly that machine.
- **Follow-up:** Track whether Arch publishes a list of affected packages and when pushes are restored.

### JFrog audits 55 advisories from one GitHub account and finds 54 fabricated, after NVD rated six SQLite CVEs critical or high

- **Category:** Security
- **Status:** confirmed
- **Sources:** [JFrog research](https://research.jfrog.com/post/sqlite-critical-cves-or-llm-slops/), [HN discussion](https://news.ycombinator.com/item?id=49154332)
- **Summary:** JFrog audited 55 advisories submitted from a single GitHub account and found 54 of them fabricated, among them six SQLite CVEs that NVD had rated critical or high. The post names checkable red flags for a fabricated record: no entry on the maintainer's own advisory page, no linked commit or pull request, empty CPE fields, and code references that do not exist in the claimed version. The post is dated 2026-07-30 and reached the Hacker News front page on 2026-08-03. The records are still moving: JFrog records Red Hat scoring CVE-2026-51302 at 10.0 Critical and downgrading it to 7.6 High between two days of writing, and JFrog reported the findings to GHSA, Red Hat and NVD.
- **Why it matters:** The MITRE submission form verifies no identity and no step in the pipeline requires a reproducible proof of concept, so a fabricated advisory reaches GHSA, downstream databases, and enterprise scanners carrying a critical score.
- **Follow-up:** Track whether GHSA, Red Hat and NVD withdraw or rescore the disputed records.

### Unit 42 recovers a threat actor's environment showing an unattended DeepSeek-driven agent chain that compromised no targets, with the three confirmed compromises coming from manual attacks

- **Category:** Security
- **Status:** confirmed
- **Sources:** [BleepingComputer report](https://www.bleepingcomputer.com/news/security/hacker-uses-deepseek-ai-to-autonomously-attack-vulnerable-servers/), [Unit 42 research index](https://unit42.paloaltonetworks.com/)
- **Summary:** BleepingComputer reports that Palo Alto Networks Unit 42 recovered an exposed environment belonging to a threat actor and reconstructed a May 2026 session in which DeepSeek drove the Hermes agent through target selection, exploit choice, and attack in a single unattended run. The operator supplied only an initial task, after which the agent pivoted from Langflow, CVE-2026-33017, to n8n on its own and downloaded exploit code chaining CVE-2026-21858 and CVE-2025-68613. Those autonomous attempts failed to compromise any target, and Unit 42 is quoted stating that the observed campaign had limited impacts. The only three confirmed compromises are Citrix NetScaler systems, CVE-2026-3055, and the report attributes them to manual attacks the operator ran against more than 460 systems rather than to the agent. The Unit 42 research index confirms a report dated 2026-07-30 on a Chinese-speaking threat actor using AI models for autonomous cyberattacks, but the index does not expose the article URL in text and the report did not resolve from this environment, so this block cites BleepingComputer as primary and the vendor index as confirmation.
- **Why it matters:** Unit 42 is quoted stating that the system executed hundreds of hours of manual targeting analysis in mere minutes, so what the recovered session bounds is analyst time rather than attacker success, and the four named CVEs are the actionable part for anyone running Langflow, n8n, or Citrix NetScaler.
- **Follow-up:** Resolve the Unit 42 report URL and check the reconstructed session against the vendor account.

## ML research

### A Locksmith Loop paper reports 91.90 percent branch coverage on one internal COBOL program when validating agent-migrated code against the original with a deterministic parity oracle

- **Category:** Paper
- **Status:** developing
- **Sources:** [paper](https://arxiv.org/abs/2607.28271), [HN discussion](https://news.ycombinator.com/item?id=49150773)
- **Summary:** The preprint describes Locksmith Loop, a method that validates agent-migrated COBOL against the original program with a deterministic parity oracle. The 91.90 percent branch coverage figure describes one of three case studies, an internal production-like COBOL program, and the abstract reports nearly complete coverage for the two open-source programs. The corpus spans 430 to 4,114 source lines. The method instruments the COBOL source and the generated Java with mocks and runs both off-mainframe on commodity hardware.
- **Why it matters:** The contribution is a deterministic oracle for agent output rather than a model score, so the check does not depend on a second model agreeing with the first.
- **Follow-up:** Preprint with no peer review. Track whether the parity oracle is reproduced outside the authors' corpus.

## Security

### RFC 9851 puts TLS 1.2 in feature freeze and states that post-quantum cryptography for it will not be specified at any time

- **Category:** Security
- **Status:** confirmed
- **Sources:** [RFC 9851](https://www.rfc-editor.org/rfc/rfc9851.html), [HN discussion](https://news.ycombinator.com/item?id=49150181)
- **Summary:** RFC 9851 places TLS 1.2 in feature freeze. The only additions still permitted are urgent security fixes decided by working group consensus, ALPN protocol identifiers, and exporter labels. The document states that post-quantum cryptography for TLS 1.2 will not be specified at any time, and that anyone deploying post-quantum cryptography should expect to use TLS 1.3. The document states twice that the freeze applies to TLS only and does not apply to DTLS in any DTLS version.
- **Why it matters:** A TLS 1.2 endpoint now has a fixed capability ceiling, so a post-quantum migration plan that assumes TLS 1.2 will eventually carry the new key exchanges has no specification to wait for.
