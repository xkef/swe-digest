## Top stories

### Apple patched an exploited CoreGraphics bug, researchers published the PDF font path (CVE-2026-86950)

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://calif.io/research/the-great-glyph-grift), [discussion](https://news.ycombinator.com/item?id=49915669)
- **Blurb:** Calif published the full PDF font trigger for CVE-2026-86950, an out-of-bounds write Apple patched after in-the-wild use.
- **Summary:** Calif describes a malicious PDF with a crafted font reaching an out-of-bounds write through undefined double-to-int32 conversion in the anti-aliased rasterizer, patched by a clamp added to `aa_double_to_fixed` in iOS 26.7.1, with an `aa_moveto` versus `aa_lineto` instruction differential, an undersized coverage buffer in `aa_cache_render`, and a reproduction harness. The stated delivery path is a possible zero-click WhatsApp message, and the post records WhatsApp 26.37.73 and 26.38.74 adding strict PDF validation in Meta's Kaleidoscope parser, with new defect tags that raise the attachment risk score and prevent automatic parsing. Apple advisory language quoted by Calif describes an extremely sophisticated attack against specific targeted individuals reported by Meta Product Security, and that advisory was not read directly.
- **Why it matters:** A working trigger is now public for any device still running iOS before 26.7.1.
- **Follow-up:** Whether Apple publishes the CoreGraphics detail directly, and whether other PDF-rendering clients add equivalent font validation.

### Matthew Green on whether sandboxing can contain rogue agents

- **Category:** Agentic coding
- **Status:** discussion
- **Sources:** [primary](https://blog.cryptographyengineering.com/2026/09/30/is-sandboxing-sufficient-to-contain-rogue-agents/), [discussion](https://news.ycombinator.com/item?id=49917378), [lab counterpoint](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-argon/)
- **Blurb:** Matthew Green argues agent sandboxing only moves the problem to the monitor, which must itself be a model to be useful.

### OpenSSL advisory covers nine issues, one High severity DTLS heap disclosure

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://openssl-library.org/news/secadv/20260929.txt), [discussion](https://news.ycombinator.com/item?id=49906844)
- **Blurb:** OpenSSL's 2026-09-29 advisory covers nine issues, led by a High severity DTLS flaw that leaks heap memory to the peer.
- **Summary:** CVE-2026-84782 lets a DTLS retransmission fired during a suspended write read past the message buffer and send heap memory to the peer as plaintext handshake data, or crash when the read reaches an unmapped region. ### Cloudflare commits to post-quantum Merkle Tree TLS certificates, first issuance targeted for Q1 2027

- **Category:** Security
- **Status:** developing
- **Sources:** [primary](https://arstechnica.com/security/2026/09/cloudflare-plans-to-issue-quantum-safe-tls-certificates/), [discussion](https://news.ycombinator.com/item?id=49908627)
- **Blurb:** Cloudflare targets Q1 2027 for its first Merkle Tree TLS certificates, keeping post-quantum handshakes near 40 KB.
- **Summary:** Ars Technica reports that Cloudflare plans to issue quantum-safe TLS certificates built on the Merkle Tree Certificate design, with first issuance targeted for the first quarter of 2027. Naive post-quantum X.509 would add roughly 40 times the TLS handshake data. The Merkle Tree design, credited to Google and announced in February, replaces the chain of quantum-vulnerable signatures with compact Merkle proofs, where a CA signs a single tree head representing millions of certificates and the browser usually handles a lightweight landmark proof, dropping handshake data to about 40 KB. A separate stated benefit is that transparency logging becomes part of issuance, quoted from Cloudflare engineer Mari Galicer as transparency becoming a requirement for operation rather than an add-on. Cloudflare's own post was not resolved after two slug attempts, so the detail here is Ars Technica quoting Cloudflare engineers.
- **Why it matters:** Handshake size, not the algorithm, is the practical blocker for post-quantum certificates, and a dated issuance target gives operators something to plan against.
- **Follow-up:** Whether Cloudflare publishes the design post directly, and whether browsers and other CAs commit to the same format.

### OpenZL ships a native LZ engine with decompression over 2x faster than Zstandard

- **Category:** Dev tools
- **Status:** confirmed
- **Sources:** [primary](https://openzl.org/blog/2026-09-29-lz-in-openzl/), [discussion](https://www.reddit.com/r/programming/comments/1wuf5lf/openzl_v02_decompression_2x_faster_than_zstandard/)
- **Blurb:** OpenZL's own LZ engine decompresses over 2x faster than Zstandard, with benchmark tables run on v0.3.0.
- **Summary:** The native LZ engine ships starting in v0.2.0, and the published benchmark tables were run with v0.3.0, reporting decompression over 2x faster than Zstandard across the compression level range and up to 50% faster than LZ4. Freedom from the Zstandard wire format lets offsets be bucketed by a V-optimal histogram and bitpacked with no entropy codec, decoding 2x to 3.5x faster. PivCo Huffman, a new Huffman layout by Marcin Zukowski, replaces the codec that accounted for over half of LZ decompression CPU and is enabled by default in v0.3.0.
- **Why it matters:** The gains come from two independent sources, an unconstrained wire format and a new Huffman layout, so only the first is limited to pipelines that control both ends.
