## Top stories

### OpenSSH 10.5 ships three security fixes and the project says it will release more often because AI-assisted reports keep finding real bugs

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://www.openssh.org/releasenotes.html#10.5), [discussion](https://news.ycombinator.com/item?id=49261895)
- **Summary:** The OpenSSH 10.5 release notes record three security fixes. The project states it will move to a more frequent release cadence, and gives as the reason that AI-assisted vulnerability reports keep surfacing real bugs, so it assumes adversaries who do not report can reach the same bugs.
- **Why it matters:** OpenSSH sits on nearly every server and developer machine, and the project is changing how often it ships rather than only commenting on report volume.
- **Follow-up:** Whether the stated cadence holds, and what the next releases carry.

### A public exploit lands for CVE-2026-53361, an AF_UNIX garbage collection race the author uses to escape containers

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://nvd.nist.gov/vuln/detail/CVE-2026-53361), [exploit](https://github.com/sgkdev/bad_garbage), [advisory](https://www.debian.org/security/2026/dsa-6381), [discussion](https://news.ycombinator.com/item?id=49267550)
- **Summary:** NVD published CVE-2026-53361 on 2026-07-04 at CVSS 7.1 from the kernel.org CNA. NVD describes a race condition in `AF_UNIX` garbage collection, where `unix_gc()` could run with `gc_in_progress` false when work is scheduled while it is already running and `unix_peek_fpl()` relies on that flag, and records the fix as setting `gc_in_progress` to true in `unix_gc()`. The CNA vector `CVSS:3.1/AV:L/AC:L/PR:L/UI:N/S:U/C:N/I:H/A:H` records local access and low privileges as required and no confidentiality impact, with fixes in 6.6.144, 6.12.95, 6.18.38, and 7.1, and Debian DSA-6381-1 records 6.12.95-1 for trixie. A public repository now carries exploit code, and the container escape, the use-after-free framing, and the claim that Ubuntu 24.04 HWE 6.17 and RHEL 10 remain unpatched are the exploit author's alone and were not verified for this digest.
- **Why it matters:** Anyone running untrusted or multi-tenant containers on an unpatched 6.12, 6.17, or 6.18 kernel now faces public exploit code rather than a patch note, and the fixed stable versions are the check to run.
- **Follow-up:** Whether distributions confirm or refute the unpatched claims for Ubuntu 24.04 HWE and RHEL 10.

### Mojo reaches 1.0 with a primarily-additive change policy, while the compiler stays closed

- **Category:** Languages
- **Status:** confirmed
- **Sources:** [primary](https://www.modular.com/blog/modular-26-5-mojo-1-0-is-here), [discussion](https://news.ycombinator.com/item?id=49261128)
- **Summary:** Modular released Mojo 1.0 as part of Modular 26.5 and states that changes during the 1.x timeframe should primarily be additive, while adding that breaking changes may still be made and will be managed the way mature languages such as C++ evolve. The compiler remains closed source, and Modular restates a commitment to open source the Mojo compiler and toolchain in 2026 and to progressively open source more of the language. The release comes under Qualcomm ownership of Modular.
- **Why it matters:** Mojo has been unstable enough that long-term projects were hard to maintain, and 1.0 is the point where Modular asks teams to build on it, with the compiler still unreleased.
- **Follow-up:** Whether the 2026 date for opening the compiler is met, and how breaking changes are handled across the 1.x releases.

### CloudSEK publishes a victim list for the March 2026 LiteLLM supply chain compromise, naming 2,500 organizations and 434,000 CI/CD pipelines

- **Category:** Security
- **Status:** developing
- **Sources:** [primary](https://www.cloudsek.com/blog/ai-supply-chain-breach-2500-companies-434000-cicd-pipelines), [discussion](https://news.ycombinator.com/item?id=49255598)
- **Summary:** CloudSEK describes the March 2026 LiteLLM supply chain compromise as running through an unpinned scanner invoked in a CI job and a Python `.pth` file that executes at interpreter startup, inside a publication window it puts at 40 minutes. CloudSEK states the figures of 2,500 organizations and 434,000 CI/CD pipelines come from a reconstructed exposure dataset and are not proof that any listed organization was compromised. The post also carries an exposure checker that collects contact details, so the numbers are recorded here as CloudSEK's own.
- **Why it matters:** Execution at interpreter startup through a `.pth` file means `--ignore-scripts` did not help, and credentials reachable in that window stay valid unless rotated.
- **Follow-up:** Independent confirmation of the exposure dataset, and any statement from the LiteLLM maintainers.

### NVIDIA releases NeMo Switchyard, an open source model-routing library, with partner cost figures

- **Category:** AI
- **Status:** confirmed
- **Sources:** [primary](https://blogs.nvidia.com/blog/nemotron-lightning-switchyard-rtx-dgx/), [discussion](https://news.ycombinator.com/item?id=49263340)
- **Summary:** NVIDIA released NeMo Switchyard as an open source library that routes each step of an agent workflow to a model chosen from a developer's own mix of open, proprietary, and NVIDIA models, selected on quality, latency, and cost. - **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://www.checklyhq.com/blog/metabase-security-incident/), [discussion](https://news.ycombinator.com/item?id=49253669)
- **Summary:** Checkly states an attacker exploited a zero-day in Metabase Cloud on 2026-08-03 and read its analytics warehouse for about 26 minutes. Checkly states Metabase discovered the intrusion the same day, blocked the endpoints used, patched the vulnerability, and published a security update, that customers, law enforcement, and a third-party forensics firm were notified on 2026-08-06, and that Checkly closed its investigation on 2026-08-10. - **Follow-up:** Metabase's advisory, the fixed version, and whether self-hosted installations are affected.

### Expat 2.8.3 fixes CVE-2026-72522, an out-of-bounds read in UTF-16 decoding reachable over the network

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://blog.hartwork.org/posts/expat-2-8-3-released/), [discussion](https://news.ycombinator.com/item?id=49257903)
- **Summary:** Expat 2.8.3 fixes CVE-2026-72522, which the maintainer describes as technically an out-of-bounds read in UTF-16 decoding whose practical symptom is easy and reliable denial of service through an infinite loop. The maintainer states the flaw needs no local access and that the NVD vector nonetheless records the attack vector as Local. The release also fixes a regression in 2.8.2 that wrongly rejected XML content of 2 GiB or more as out of memory on 32-bit platforms and on 64-bit Windows. The Mozilla Security Team reported the vulnerability.
- **Why it matters:** Expat is bundled and pinned across a large part of the C and Python stack, so the fix has to travel through many vendored copies, and a severity triage that reads the NVD vector alone will score it too low.
- **Follow-up:** Whether the NVD vector is corrected, and downstream rebuilds of vendored copies.

## Infrastructure

### pg_clickhouse v0.10.0 pushes down 16 of 22 TPC-H queries and adds guards for a NULL semantics mismatch that silently inverted NOT IN

- **Category:** Infrastructure
- **Status:** confirmed
- **Sources:** [primary](https://clickhouse.com/blog/pg_clickhouse-whats-new-july-2026), [discussion](https://news.ycombinator.com/item?id=49265031)
- **Summary:** ClickHouse reports that pg_clickhouse v0.10.0 pushes 16 of 22 TPC-H queries down to ClickHouse. The release adds guards for a semantics mismatch in `IN`, where ClickHouse uses two-valued logic and PostgreSQL uses three-valued, so a naive pushdown of `NOT IN` returned rows PostgreSQL would have filtered out.
- **Why it matters:** The mismatch produced wrong results under a plan that looked correct, which is the failure mode a pushdown extension has to close before its benchmark numbers mean anything.
