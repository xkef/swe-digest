## Top stories

### Citrix confirms two actively exploited NetScaler zero-days and CISA orders federal patching by 2026-09-30

- **Category:** Security
- **Status:** confirmed
- **Sources:** [BOD 26-04](https://www.cisa.gov/news-events/directives/bod-26-04-prioritizing-security-updates-based-risk), [CISA KEV catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog), [coverage](https://www.bleepingcomputer.com/news/security/cisa-orders-feds-to-patch-exploited-citrix-flaws-by-wednesday/)
- **Blurb:** Citrix confirmed CVE-2026-88771 and CVE-2026-88772 in NetScaler under active exploitation, with a federal patching deadline of 2026-09-30.
- **Summary:** CVE-2026-88771 affects all NetScaler ADC and Gateway deployments in their default configurations, and CVE-2026-88772 requires DTLS, which Citrix notes is enabled by default on VPN virtual servers. Fixed build numbers are not stated here because the Citrix bulletin at community.citrix.com returned 403 to automated fetch and both NVD detail pages rendered empty, leaving the KEV entries, which list both CVEs as under active exploitation, as the primary record. Shadowserver tracks over 23,000 IP addresses with NetScaler fingerprints, nearly 22,000 ADC and just over 1,500 Gateway, with no information on how many are honeypots, already patched, or vulnerably configured.
- **Why it matters:** Two unauthenticated remote code execution paths are being exploited on an appliance that terminates remote access, and CISA states the updates may result in loss of forensic visibility, which is what tells an operator whether an appliance was already taken.
- **Follow-up:** Watch for the Citrix bulletin becoming fetchable, NVD scoring, and any incident-response guidance on evidence preservation before patching.

### ShinyHunters bypasses PeopleSoft WAF rules with a percent-encoded path

- **Category:** Security
- **Status:** confirmed
- **Sources:** [report](https://www.bleepingcomputer.com/news/security/shinyhunters-uses-waf-bypass-trick-in-oracle-peoplesoft-attacks/)
- **Blurb:** ShinyHunters bypassed PeopleSoft WAF rules with a percent-encoded path, invalidating the mitigation Mandiant advised in June.
- **Summary:** The group requests /%50SEMHUB/ instead of /PSEMHUB/, so a WAF rule matching the literal endpoint string does not fire while the application server decodes the path and serves the request, which invalidates the endpoint-blocking mitigation Mandiant recommended in June for CVE-2026-35273. Mandiant advises operators to search WebLogic access logs for both forms and states the actual fix is the Oracle security update rather than any WAF rule, while Google warns the group may switch to other percent-encoded or mixed-case variants. Affected PeopleSoft versions are not stated in the available reporting, and Mandiant's own report URL did not resolve, so the detail here comes from BleepingComputer quoting it.
- **Why it matters:** Any defence that pattern matches a request path before the application server decodes it can be stepped around by encoding one character, so operators who blocked an endpoint at the WAF instead of patching CVE-2026-35273 are exposed again.

### A researcher publishes the full LuaRocks.org exploit chain

- **Category:** Security
- **Status:** confirmed
- **Sources:** [writeup](https://vhyrro.neorg.org/posts/critical-luarocks-exploit-cve/), [discussion](https://news.ycombinator.com/item?id=49870377)
- **Blurb:** A researcher published the full LuaRocks.org chain, from a patched LuaJIT bytecode instruction to root on the registry host.
- **Summary:** The writeup traces the chain end to end, starting from a LuaJIT bytecode instruction the sandbox did not account for and ending at root on the registry host. The sandbox itself was carefully built, and the defeat came from the registry accepting precompiled bytecode rather than source only.
- **Why it matters:** The writeup shows a well built Lua sandbox defeated entirely by accepting precompiled bytecode, which is the same mistake any registry that evaluates user-supplied manifests in-process can make.
- **Follow-up:** The LuaRocks incident led the 2026-09-27 digest and now has a complete public exploit chain, so track remediation on the registry and whether other package registries that accept bytecode respond.

### Cloudflare reports a cross-tenant data exposure in Containers and Sandboxes

- **Category:** Security
- **Status:** confirmed
- **Sources:** [report](https://www.bleepingcomputer.com/news/security/cloudflare-fixes-containers-cross-tenant-flaw-exposing-customer-data/), [discussion](https://news.ycombinator.com/item?id=49870848)
- **Blurb:** Cloudflare fixed a cross-tenant exposure in Containers and Sandboxes where reused storage blocks were handed over without zeroing.
- **Summary:** Storage blocks from a shared pool were handed to a new tenant without being zeroed first, so a container could read data written by a previous occupant, and the researchers found residual material on 18 of 24 container placements and across 20 of 22 underlying nodes tested, including directory structures, database pages, and structurally complete SQLite databases. Their scripts returned aggregate counts rather than disk contents, so no real customer data was exposed in the evaluation, and Cloudflare states it found no evidence in logs, telemetry, or historical data that customer data was exposed by this method. The fix was applied to Cloudflare infrastructure rather than shipped as a version, all mitigation finished on 2026-09-19, and Cloudflare states customers need take no action.
- **Why it matters:** A shared storage pool that hands reused blocks to a new tenant without zeroing them crosses the isolation boundary that multi-tenant serverless platforms are sold on.
- **Follow-up:** Cloudflare's blog index lists a Containers disclosure post dated 2026-09-24 that no slug resolved to automated fetch, so watch for that vendor post becoming reachable, and for further multi-tenant findings from Accomplish, credited with this report and with the SharedRoot Claude Cowork sandbox escape.

## ML research

### Aggressive post-training quantization makes reasoning models overthink

- **Category:** Paper
- **Status:** confirmed
- **Sources:** [paper](https://arxiv.org/abs/2606.00206), [discussion](https://news.ycombinator.com/item?id=49869861)
- **Blurb:** A paper finds aggressive post-training quantization makes reasoning models overthink, and a training-free logit penalty cuts the cost.
- **Summary:** The authors report that quantized reasoning models reached the correct answer in intermediate steps but failed to emit it in up to 52 percent of failures, spending additional chain-of-thought tokens instead. A training-free logit penalty on overthinking markers reduces chain-of-thought length by 12 to 23 percent while preserving or improving accuracy across 5 models, 3 quantization methods and 5 benchmarks, and reduces overthinking errors by up to 58 percent. Submitted 2026-05-29.
- **Why it matters:** Anyone quantizing a reasoning model to cut serving cost may be paying that saving back in chain-of-thought tokens.

### Two actions-cool GitHub Actions served the Mini Shai-Hulud payload for nine days before being disabled again

- **Category:** Security
- **Status:** confirmed
- **Sources:** [report](https://www.bleepingcomputer.com/news/security/github-actions-re-enabled-with-mini-shai-hulud-payload-still-active/)
- **Blurb:** actions-cool/issues-helper and actions-cool/maintain-one-comment served Mini Shai-Hulud code from 2026-09-16 until 2026-09-25.
- **Summary:** Both actions were restored to the marketplace with release tags still resolving to the Mini Shai-Hulud credential-stealing payload, so workflows referencing them by mutable version tag ran that code between 2026-09-16 and 2026-09-25. GitHub disabled both again on 2026-09-25, so workflows referencing them now fail rather than execute the payload. - **Why it matters:** GitHub's dependency graph lists about 15,000 repositories depending on issues-helper alone, and each one that referenced a mutable version tag rather than a commit SHA ran attacker-controlled code for those nine days.

- **Category:** Languages
- **Status:** confirmed
- **Sources:** [survey](https://shnatsel.github.io/state-of-simd-rust-2026/), [discussion](https://news.ycombinator.com/item?id=49844629)
- **Blurb:** A Fearless SIMD maintainer surveys SIMD in Rust and finds runtime multiversioning is what separates the available crates.
- **Summary:** The survey gives per-crate feature and instruction-set tables and concludes that support for runtime multiversioning is the practical dividing line between the libraries. It names two traps in particular: std::simd silently emitting scalar code when LLVM lacks a matching operation, and wide being incompatible with runtime feature dispatch. Published 2026-09-25.

## Linux and kernel

### Jens Axboe posts an io_uring RFC that swaps thread identities on block

- **Category:** Linux/Kernel
- **Status:** developing
- **Sources:** [LWN](https://lwn.net/SubscriberLink/1094303/bf025f98cb71f941/), [discussion](https://news.ycombinator.com/item?id=49871981)
- **Blurb:** Jens Axboe posted an io_uring RFC that swaps thread identities when an operation is about to block, reporting large fsync gains.
- **Summary:** The RFC pays for a worker thread only when an operation actually blocks, rather than up front, by exchanging thread identities at that point. A tmpfs fsync benchmark reported a gain of nearly 700 percent, while other gains are more modest and tests that always block show regressions, worst at higher queue depth because serialising submissions removes the parallelism that immediate worker handoff provided. The approach hooks the scheduler and depends on proving nothing else in the kernel holds a reference to the task_struct being exchanged, and it was posted 2026-09-17.
- **Why it matters:** If the task_struct ownership question can be settled, io_uring stops paying worker-thread cost for operations that never block.
- **Follow-up:** Watch for maintainer response on the scheduler hook and on task_struct reference safety, and whether this progresses past RFC.
