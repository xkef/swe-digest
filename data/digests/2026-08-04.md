### Cloudflare ships @cloudflare/computer, an agent runtime spanning isolates and containers

- **Category:** Infrastructure
- **Status:** confirmed
- **Sources:** [announcement](https://blog.cloudflare.com/cloudflare-computer/), [source](https://github.com/cloudflare/computer), [discussion](https://news.ycombinator.com/item?id=49155598)
- **Summary:** Cloudflare released @cloudflare/computer, a runtime that presents one interface over an isolate shell and a container shell. Both are backed by a SQLite-backed durable filesystem. The source is published on GitHub.
- **Why it matters:** Putting a durable filesystem behind both execution modes means agent sandboxing stops being one container per agent, which Cloudflare argues does not scale.

## AI

### Cloudflare quantizes KV cache and weights to serve Kimi and GLM

- **Category:** AI
- **Status:** confirmed
- **Sources:** [primary](https://blog.cloudflare.com/smaller-faster-safer-models/), [discussion](https://news.ycombinator.com/item?id=49158581)
- **Summary:** Cloudflare published per-concurrency measurements rather than a single headline number. An FP8 KV cache loses a few percent per token but admits 64 concurrent requests where BF16 exhausts memory at 32. INT4 weights shrink a GLM 5.2 checkpoint from 705 GB to 421 GB with accuracy within 0.8 points.
- **Why it matters:** The numbers state the quantization tradeoff as a concurrency ceiling rather than a quality score, which is the form the decision actually takes when sizing inference capacity.

## Security

### DPRK npm packages hide their C2 address in the recipient of an empty Ethereum transfer

- **Category:** Security
- **Status:** confirmed
- **Sources:** [analysis](https://opensourcemalware.com/blog/nullreceiver-dprk-c2-technique), [discussion](https://news.ycombinator.com/item?id=49154571)
- **Summary:** Two trojanized Tailwind CSS plugin clones, bianira-ui@1.27.0 and fluid-type-ui@2.0.8, decode a command-and-control IP address from the destination address bytes of a zero-value, zero-data Ethereum transfer. The transfer carries no calldata and no funds, so the address field is the entire payload.
- **Why it matters:** Detections built around EtherHiding's fixed burn address and calldata inspection do not fire on this variant.
- **Follow-up:** Watch for further packages using the same encoding.

## Outages

### DDoS against Norway's ID-porten degrades national login for a second day

- **Category:** Outage
- **Status:** confirmed
- **Sources:** [status page](https://status.digdir.no/incidents/d7hvqmf2yr3l), [discussion](https://news.ycombinator.com/item?id=49160631)
- **Summary:** Digdir's status page records a denial-of-service attack against ID-porten that began about 01:00 on 2026-08-03 and degraded login for a second consecutive day. The page lists the affected services as ID-porten and MinID, eFormidling, ELMA, Selvbetjening, Altinn, Kontakt- og reservasjonsregisteret, eInnsyn, Maskinporten and Ansattporten. ID-porten is operated by Digdir's operating partner Vivicta. The incident is unresolved as of the status page update timestamped 2026-08-04 00:08 CEST.
- **Why it matters:** One identity provider degraded login to Norwegian public services across roughly ten named dependent services, which is the concentration risk of national single sign-on in practice.
- **Follow-up:** Track Digdir's post-incident report for attack volume and mitigation.

### Twenty years of Pandoc

- **Category:** Dev tools
- **Status:** confirmed
- **Sources:** [primary](https://pandoc.org/twenty-years-of-pandoc.html), [discussion](https://news.ycombinator.com/item?id=49156750)
- **Summary:** John MacFarlane traces Pandoc from roughly 3000 lines of Haskell to 51 input and 76 output formats, crediting the central AST with readers and writers on either side. The post also explains why the author of the CommonMark spec still ships a pre-CommonMark Markdown parser.

- **Status:** developing
