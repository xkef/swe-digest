## Top stories

### Cloudflare fixes a cross-tenant data exposure in Containers

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://blog.cloudflare.com/containers-cross-tenant-vulnerability/), [discussion](https://news.ycombinator.com/item?id=49831647)
- **Blurb:** Cloudflare fixed a Containers flaw that handed new tenants unzeroed 64 KiB disk blocks holding other customers' data.
- **Summary:** Cloudflare reports that a Workers Paid account could read residual disk blocks left behind by other customers' Containers, including directory structures, database pages, and structurally complete SQLite databases, because the dm-thin pool ran with `skip_block_zeroing` and handed reused 64 KiB blocks to a new tenant unzeroed. Cloudflare reviewed retained disk-I/O telemetry against detection signatures built from the proof of concept and attributed every match to the researchers and its own engineers, finding no other exploitation. Beyond the configuration change it retired all running container disks and cleared each host's cached dm-thin image snapshots fleet-wide, because zeroing new allocations does not sanitize mappings already present, and Cloudflare Sandboxes, which is built on Containers, was in scope.
- **Why it matters:** Block reuse without zeroing breaks the isolation that every multi-tenant container platform sells, and the exposed material was complete enough to read as databases rather than as fragments.
- **Follow-up:** Track whether Cloudflare publishes the exposure window and any customer notification scope.

### Two compromised GitHub Actions were re-enabled with their malicious tags intact

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://socket.dev/blog/mini-shai-hulud-actions), [discussion](https://news.ycombinator.com/item?id=49837177)
- **Blurb:** Two GitHub Actions disabled in May for compromise ran again from 2026-09-16 until both were disabled again on 2026-09-25.
- **Summary:** Socket reports that two GitHub Actions repositories disabled in May over a compromise had access restored, which reactivated a months-old payload with no new attacker action. The dependency graph lists about 15,000 dependents for `issues-helper` alone. Socket's update dated 2026-09-25 states that `actions-cool/issues-helper` and `actions-cool/maintain-one-comment` have been disabled on GitHub again, so workflows referencing them now fail at job setup instead of running the payload.
- **Why it matters:** A platform decision rather than an attack re-armed a supply-chain compromise for a window running 2026-09-16 to 2026-09-25, so any workflow that referenced either action by tag inside that window ran the payload with the job token and needs every secret it could reach rotated.
- **Follow-up:** Track whether the malicious tags are removed, and whether a fuller dependent count is published.

### File-notification APIs leak user and application behaviour on four operating systems

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://inoti.fyi/), [LWN](https://lwn.net/Articles/1096431/), [report](https://www.theregister.com/security/2026/09/24/decades-old-file-security-flaws-found-in-android-linux-macos-and-windows/5298672), [discussion](https://news.ycombinator.com/item?id=49835649)
- **Blurb:** File-notification APIs let a local app watch another's activity on Linux, Android, Windows, and macOS, with only Linux partly fixed.
- **Summary:** The researchers report that read permission on a directory is enough to recover keystroke timing from `/dev/input` or `/dev/pts`, to watch another application's private WhatsApp media folder on Android, and to identify which sites another Windows user visits. Linux carries a partial mitigation as CVE-2025-68788 in 5.10.248, 5.15.198, 6.1.160, 6.6.120, 6.12.65, and 6.18.3. The Windows registry mitigation ships disabled by default, and Android and macOS have none.
- **Why it matters:** The side channel needs only read permission on a directory, so sandboxing and per-app storage separation do not bound it on three of the four systems.
- **Follow-up:** Track an Android or macOS mitigation, whether Microsoft enables the registry setting by default, and whether the Linux fix moves from partial to complete.

## ML research

### Automated C-to-Rust tools cut unsafe blocks without removing the memory bugs

- **Category:** Paper
- **Status:** confirmed
- **Sources:** [paper](https://arxiv.org/abs/2609.25682), [discussion](https://news.ycombinator.com/item?id=49826801)
- **Blurb:** A study of 464 machine-translated Rust programs found 177 inherited the C memory bugs and 77 new Rust bugs appeared.
- **Summary:** The paper runs C2Rust-analyze, CROWN, C2SaferRust, and FLOURINE over 116 buggy C programs from the NIST Juliet suite, producing 464 Rust programs. Of those, 342 failed to compile, 177 inherited the original memory security bugs, and 77 new Rust bugs appeared.
- **Why it matters:** An unsafe-block count is the usual proxy for translation quality, and these numbers show it is not evidence that a translation improved memory security.

- **Category:** Agentic coding
- **Status:** confirmed
- **Sources:** [primary](https://github.blog/changelog/2026-09-23-local-sandboxing-in-the-github-copilot-app/), [discussion](https://news.ycombinator.com/item?id=49833223)
- **Blurb:** The GitHub Copilot app gained per-project local sandboxing that errors out rather than running an unenforceable policy.
- **Summary:** GitHub added local sandboxing to the Copilot app, bounding filesystem, network, and git and GitHub CLI credential access per project. ## Security

### SourceHut build logs allowed account takeover through an ansi2html XSS

- **Category:** Security
- **Status:** confirmed
- **Sources:** [primary](https://blog.arusekk.pl/posts/srht-account-takeover/), [discussion](https://news.ycombinator.com/item?id=49835996)
- **Blurb:** An ansi2html XSS let anyone who could write to a SourceHut build log run script in every browser that viewed the job.
- **Summary:** The report describes an XSS in ansi2html rendering of builds.sr.ht job logs, tracked as CVE-2026-92973 and fixed in ansi2html 1.9.4 and builds.sr.ht 0.105.1. Getting text into a build log was enough to trigger it, including by mailing a patch to a public list with CI enabled and without holding an account. The build log page carries the CSRF token in the DOM and builds.sr.ht holds deploy keys for sr.ht itself, and the author reasons from those two facts that a payload could reach both, while stating he did not build or run one. He states the flaw sat in builds.sr.ht for about four and a half years.
- **Why it matters:** Build log output is attacker-controlled text on any CI system that accepts outside patches, and rendering it as markup let a public mailing list post execute script in the browser of everyone who read the job.

## Languages and runtimes

### Fearless SIMD reaches 1.0 with portable SIMD and no ad-hoc unsafe code

- **Category:** Languages
- **Status:** confirmed
- **Sources:** [primary](https://linebender.org/blog/fearless-simd-1-0/), [discussion](https://news.ycombinator.com/item?id=49800085)
- **Blurb:** Fearless SIMD 1.0 confines Rust SIMD unsafe code to one kernel macro and a small safe transmute module, with a three-year support commitment.
- **Summary:** Linebender released Fearless SIMD 1.0. The crate confines memory safety review to a `kernel!` macro built on target feature v1.1 and a small safe transmute module, rather than the thousands of unsafe blocks other SIMD abstractions carry. It ships a `#[simd]` multiversioning macro as `fearless_simd_macros` 0.1 and commits to three years of security updates, with 30 direct and over a thousand indirect dependents already.
- **Why it matters:** Portable SIMD in Rust has generally meant auditing unsafe intrinsic blocks per target, and this release moves that review surface into two reviewable places.
